# Desktop developer-experience fix pass

Verified on macOS, 1 October 2026, in `codex-devfix` from `c92812e7`.

## Electron dev resolution

`vite-plugin-electron/multi-env` 1.1.1 creates a detached builder during
`serve`, with `configFile: false`. It carries the Electron options and their
Rolldown plugins, but does not inherit the renderer's top-level aliases.
Production merges the Electron environments into the original config and
therefore inherits those aliases. With no alias, package subpath resolution
uses literal targets and fails on the directory import `#shared/contract`.

Vite 8 aliases are global-only. Putting `alias` in an environment's `resolve`
options is unsupported and Vite overwrites it during resolution. The fix is an
Electron Rolldown plugin in `vite.config.ts`, installed for both main and
preload. It applies the same shared alias map before delegating extension and
index resolution to Vite. No conditions, externalization policy, or application
main-process source changed.

`scripts/vite-resolution.test.ts` runs two detached, config-free builds with
file and directory imports covering `#main`, `#preload`, `#shared`, `#next`, and
`#renderer`. Both pass with the fix and fail when the plugin is removed.
A production build with development mode would not exercise this failure.
