## Systemic fixes and implementation order

1. **A — Foundations.** Preserve the real shell while its route loads; give root/fallback content a bounded full-height frame. Match skeleton geometry to chat, session start, forms, lists, settings and artifact views. Catch errors at route/pane boundaries with local recovery. Bound grids, flex rows, text and toolbar actions. Complete translations in all eleven locales, including dynamic key unions, object-valued mistakes and placeholder copy; add a failing completeness check. Establish distinct light card surfaces and readable selected/control/destructive tokens using app composition and the registry write gate where needed.
2. **B — P0 completion.** Fix Account referral availability and optional local-model loader handling. Constrain titles and Details actions. Allocate dock space from measured width, including handles and a third pane; full-view chat must not consume the dock allocation. Place toast stacks wholly inside the window. Cover actual dock panels and shell-visible mid-load states in the capture harness.
3. **C — P1.** Repair per-area content, layouts, dialogs, empty/loading/error states, tree theme, terminal titles/glyphs, setup flow and tour targets. Fix current notch labels, duplicate actions, send control, padding, content sizing and transition clipping while retaining shared geometry and its tests.
4. **D — P2 and capture fidelity.** Finish visual consistency, row actions, previews, empty groups, release copy, keyboard presentation and gallery fixtures. Replace independent notch specimen geometry with the native shape model.

Each group gets focused tests, a fresh desktop build, affected-screen recaptures in dark/light at 1440×900 and 960×640, personal PNG inspection, iteration and a commit. Captures go only to `.build/ui-audit/after/`. Every run copies the supplied real home with `scripts/cutover/perf-home.mjs`; the source home must remain hash-identical. Electron processes started by the harness are cleaned up.

No manual React memoization; React Compiler diagnostics must remain zero. Feature imports follow the entrypoint allowlist. Registry-generated `ui/` files are not edited by hand.
