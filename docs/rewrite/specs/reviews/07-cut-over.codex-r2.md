1. **Blocker — Previously archived threads become orphans on the next pass.** C1 and §9.3 claim partial commits preserve readable history. HEAD’s [step 4](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/migrations/steps/004-archive-transcripts-v1.ts) removes every v1-derived twin lacking a v1 file. After a partial commit archives A’s v1, the next pass removes A’s valid twin. The spec adds archive records but never makes this orphan sweep consult them. **Fix:** exclude twins with matching archive provenance from orphan removal; test two successive commits containing both archived and newly converted threads.

2. **Blocker — N+1 still enables the cleared-history regression before migration succeeds.** C15 constructs `ThreadStore({ v1Archived: true })` merely because step 4 is registered. If planning fails, recovery remains unresolved, or a twin cannot be inspected, orphan cleanup has not succeeded. Nevertheless, §9.3 explicitly serves a v1-derived twin with no source, record, or marker. HEAD previously treated that exact state as cleared. **Fix:** require per-thread archive evidence in N+1 too; test failed planning, unresolved recovery, and temporarily unreadable orphan twins.

3. **Blocker — Downgrading to N resets migrated preferences.** §12.4 promises “Back to N needs no restore,” while C11 makes N import legacy preferences every launch. After N+1’s step 3 removes the legacy keys, [the importer](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/config/legacy-prefs.ts) calls `resetLegacy` for their absence. Migrated theme, pins, models, and other leaves become defaults and are persisted. **Fix:** ship an N reader that distinguishes deliberate step-3 retirement from user deletion. Test N+1 → N with unchanged legacy-provenance leaves.

4. **Major — The removals index cannot restore step 3.** C1 indexes only removals, and §12.4 calls that index the only restoration input. Step 3 performs `replace-user` writes to `renderer-state.json` and `prefs.json`, not removals. Its original legacy preferences therefore never enter the index. **Fix:** index recoverable replacement backups as well, with operation type and original digest; restore `renderer-state.json` without overwriting newer authoritative `prefs.json`.

5. **Major — The index’s recovery evidence is deleted.** C1 promises rebuilding or trimming `removals.jsonl` from `commit.log`. HEAD’s [runner](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/migrations/runner.ts) deletes both journal and log after each commit; subsequent partial entries replace earlier attempt metadata. Historical index entries then have no durable commit evidence from which to rebuild. **Fix:** retain a validated per-attempt manifest and completion record with the backup, and derive the index from those records. Test damage after staging cleanup and after several partial commits.

6. **Major — Oldest-first restoration selects stale history after another migration cycle.** §12.4 restores every attempt oldest-first. After restore → legacy edits → N+1 migration → restore again, several indexed versions can name the same destination. The oldest version occupies the canonical path; newer versions become `.restored-*` files that the session does not open. **Fix:** record restoration generations and consumption state, then choose the latest applicable backup per destination. Add the complete two-cycle test.

7. **Major — The manual appendix bypasses collision protection.** The command preserves conflicting files, but the appendix simply says to move every indexed backup to its destination. That can overwrite newer history and does not reproduce archive-record cleanup or migration-state changes. R7-T15 nevertheless promises equivalent results from both procedures. **Fix:** publish a complete recovery procedure with digest checks, collision handling, step filtering, and metadata updates; test conflicting destinations through both paths.

8. **Major — Oversized history remains inaccessible in release N.** §13.4 requires an over-64 MB conversation to display after upgrading to N. C15 introduces streaming fallback only in N+1, while §5.7 calls N’s existing repair path its fallback. [That repair path](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/session/thread-store.ts) refuses conversion above 64 MB and returns no history when no twin exists. **Fix:** implement the bounded fallback in C1 and ship it in N; run the oversized-history gate against N.

9. **Major — The fallback prescription can resurrect cleared retained sources.** C15 invokes fallback whenever no usable twin exists and a transcript remains. A failed deletion leaves precisely that state, protected by `<id>.cleared`; C15 also removes dual-removal. The fallback’s stated predicate contains no clear-marker check. **Fix:** apply the existing fingerprint/token clearing rules before fallback conversion, including streaming fingerprint calculation. Test clearing retained oversized history with failed deletion and restart.

10. **Major — Build provenance conflicts with cached builds.** C4 rejects differing renderer and agent commit stamps, but [Turbo caches `dist/**`](/Users/rajaniraiyn/work/abacusai-bot/turbo.json) by task inputs, without a Git commit input. An agent-only hotfix can rebuild the agent while restoring an unchanged renderer stamped with an earlier commit, causing a legitimate experience to fail packaging. **Fix:** include the pinned provenance commit in both build cache keys, or specify compatible per-component provenance. Test a renderer cache hit during an agent-only hotfix.

11. **Major — Both deletion checkers prescribe an unavailable API.** §§5.1 and 5.6 require `ts.preProcessFile`. Installed [TypeScript 7.0.2](/Users/rajaniraiyn/work/abacusai-bot/node_modules/typescript/package.json) exports only version information from its package root; the read-only probe fails with `TypeError: ts.preProcessFile is not a function`. **Fix:** select and declare a supported parser, such as the installed OXC parser, and test all required import forms through that actual API.

12. **Major — C5 validates consumers against the wrong renderer tree.** §11 permits consumer files only under `src/renderer` or `src/main`. At C5 the active implementation still lives under `src/renderer-next`; C7 moves it later. Genuine consumers fail validation, while references to obsolete legacy symbols can pass. **Fix:** validate against `src/renderer-next` through C6, then rewrite and revalidate references in C7.

13. **Major — The swap snapshot omits unsent draft state.** C3 transfers composer text, selection, focus, and scroll. Spec 02 §8.7 also stores attachments, mode, and model in document `sessionStorage`; spec 03 stores creation drafts there. A new experience uses a different `app://bundle.<hash>` origin and cannot inherit that storage. **Fix:** transfer the complete typed draft state and relevant unsaved forms before exposure. Extend R7-T3 with attachments and partially completed forms.

14. **Major — Packaged smoke still exits before the new markers.** C4 adds readiness markers and makes CI wait for them, but never changes [the immediate `app.exit(0)`](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/index.ts:2131) after the main-process marker. R7-T16 also requires notch readiness unconditionally on macOS, although spec 06 correctly permits no companion after an unavailable probe. **Fix:** delay smoke exit until required readiness outcomes finish; accept an asserted disabled-companion outcome where appropriate, with a bounded failure timeout.

15. **Major — The script canary is declared an entry point.** C7 lists every `scripts/*.{js,mjs}` file as a knip entry, while R7-T22 requires an unused script canary to be reported. An added root-level `.mjs` canary matches that entry glob and is treated as reachable. **Fix:** enumerate actual executable scripts, leave helper scripts in project scope, and plant the canary outside every entry pattern.

16. **Major — The halt rule omits transfers already in progress.** §12.2 describes residual installation within the two-check window, and R7-T33 tests already-downloaded clients. [UpdateService](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/updates/update-service.ts) suppresses periodic checks while downloading, resets strikes on completion, and can restart an idle app at the next one-minute poll. A slow transfer can therefore install long after the stated halt window. **Fix:** explicitly document this shipped-client limitation, test halt during download, and add transfer cancellation or withdrawal-aware installation suspension to clients that can still be changed.
