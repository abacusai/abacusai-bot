1. **Major. §§3.2–3.3 promise shared readiness, but recovery replaces the generation without settling its existing waiters.** A `load()` caller holds generation G’s promise. If replay fails before checkpoint N, recovery creates G+1; resolving G+1’s readiness does not resolve G’s promise. The awaiting route can remain pending indefinitely. **Fix:** carry waiters across recovery, or explicitly chain superseded readiness promises to the replacement generation. Test two awaiting loaders with replay failure before N, recovery, and retirement.

2. **Major. §3.5 claims the host object `satisfies UseChatReturn`.** Its `sendMessage` returns `session.submit()`, declared as `Promise<AdmissionResult>` in §3.7. The ai-react 0.29.3 reference source requires `Promise<void>` for `sendMessage`; `reload` also requires `Promise<void>`. The supplied binding cannot type-check as written. **Fix:** use async wrappers that await admission and return nothing, while preserving admission results on the session API for composer handling. Make R2-T2 compile this exact binding.

3. **Major. §10 claims `MAX_ROWS = 400` bounds mounted content, but its expansion rules remove that bound.** “Show earlier” mounts another 100 rows, tool disclosures expand in batches of 100, and rows are unmounted only at the end. Repeated expansion while reading can mount the entire history or all 3,000 tools. R2-T31 measures initial mounting without exercising this path. **Fix:** define a bounded moving window with anchor-preserving eviction, or make expanded history a separately bounded view. Test repeated history and tool expansion while away from the end.

4. **Major. §8.5 requires `queue.command_rejected` to display an error, but §4.2 discards it.** The mapping table has no handler for that event, and its catch-all explicitly ignores unknown `CUSTOM` names. The authoritative `queue.updated` refresh cannot supply the rejection reason or produce “That message already went out.” **Fix:** add a mapped rejection handler and per-command error state, with incarnation and generation guards. Extend R2-T21 to assert the rendered rejection message.

5. **Major. §§3.7/4.6 treat every `ai.send` timeout as a failed admission.** The agent writes `run.ack {started}` before emitting the run and user echo. Losing or timing out the RPC response can therefore leave an accepted run streaming while the renderer removes its outbox entry and restores the draft with “The agent isn't ready.” Resubmission generates a new run ID, defeating the host’s run-ID deduplication and potentially submitting the prompt twice. **Fix:** distinguish definitive rejection from uncertain delivery; reconcile by the original run/message IDs and retry uncertain admission with the same run ID. Test acceptance followed by a lost acknowledgement, including an echo arriving before the RPC rejection.
