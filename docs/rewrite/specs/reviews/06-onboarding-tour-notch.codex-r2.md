1. **Blocker — §10.1 still adopts a clone-derived recipe.** It calls PLAN’s window recipe “the user’s decision,” but PLAN explicitly attributes that combination of window options and follow-up calls to openbot.run. Electron documenting individual APIs does not establish independent provenance for the recipe. **Fix:** replace that prescription with independently derived requirements and hardware-tested choices; remove the clone-derived recipe from PLAN too.

2. **Blocker — §14 inherits a prohibited sound constant.** “The cue set and synthesis are 03 §17” imports the 220 ms swept-sine `done` recipe that 03 explicitly attributes to openbot.run. Changing its gain to 0.08 does not remove that derivation. **Fix:** replace the inherited recipe with an independently designed or licensed cue and amend 03 and PLAN.

3. **Major — §6.5 still loses the completion target.** The tail clears `onboardingExit` before navigating or starting the tour. Quitting after that write leaves an onboarded account with no recovery target. A failed navigation has the same problem. **Fix:** retain the exit until the destination commits; represent tour startup separately if it must survive interruption. Extend R6-T6 through cleanup, navigation and tour-start boundaries.

4. **Major — §6.5’s funnel deduplication claim is false.** It says main’s beacon is at-most-once per name. `main/index.ts` calls `reportFunnelStep`, not `reportFunnelStepOnce`; the former sends every call. OB14 also reports `onboarding_done` upon entering `done`, before completion. **Fix:** emit completion only after the account commit, and explicitly implement the required deduplication.

5. **Major — §6.2’s pure guard lacks a required input.** It distinguishes an existing own bot from one created by this document, but `FlowFacts` contains only `ownsBot`, and `guardStep` receives only facts and the sign-in attempt. It cannot implement that exception. **Fix:** pass the first-bot creation state or an explicit `createdBotId`; test revalidation after the optimistic insert and persistence echo.

6. **Major — §§6.2–6.4 reject the sign-in error state.** `connect` is valid only for a `pending` attempt, while `auth-failed` must leave it displaying an error and Try again. Once the attempt is settled, route revalidation redirects to welcome. **Fix:** distinguish a retained failed attempt from a cold URL, and test invalidation/revalidation while the error is displayed.

7. **Major — §8.3 reuses a deletion helper with incompatible navigation.** Spec 03 §§5.5/6.4 define bot deletion as navigating away before deleting. Calling that helper during onboarding can navigate toward the shell while `onboarded` remains false, instead of staying on the step through failures and then reaching `done`. **Fix:** separate persistence-only deletion from route navigation, or add an explicit navigation policy.

8. **Major — §8.3 does not establish the routine-deletion persistence boundary.** TanStack DB’s `delete()` returns a transaction; calling or awaiting that return value does not await persistence. Bot deletion can therefore proceed before routine deletion fails. **Fix:** explicitly await `routinesCollection.delete(id).isPersisted.promise` before deleting the bot. R6-T9 should hold and reject the real transaction, rather than merely assert call order.

9. **Major — §11.6’s cancellation contract is missing.** Spec 02 defines `ThreadSession.load(): Promise<void>` with shared readiness and no signal argument. §23.2 adds a cache budget and external retirement, but never adds the claimed signal covering hydration and replay. **Fix:** specify how the director cancels its load, including shared callers and timeout retirement; test that stalled hydration and its iterator actually terminate.

10. **Major — §§10.2/11.6 can wait forever for shrink completion.** Reduced motion removes the size transition; interruption can cancel it; unchanged dimensions start none. These cases produce no `transitionend`. **Fix:** handle cuts immediately, track both dimension transitions, handle cancellation, and guard completion callbacks by generation. Add real-browser interrupted and reduced-motion shrink cases. [CSS transition event rules](https://drafts.csswg.org/css-transitions-1/#transition-events).

11. **Major — “larger” versus “smaller” rectangles omits mixed dimension changes.** A 500×32 working shape can become a 440×108 approval: width contracts while height grows. Applying the final native rectangle before animation clips the old width; delaying it clips the growing height. **Fix:** first allocate an envelope containing both shapes, then apply the final bounds after the transition. Test changes in both directions, including upward Windows growth.

12. **Major — §14.2’s fallback violates focused-thread silence.** Main correctly declines to claim a cue for its visible, focused thread. The notch player deliberately reports both visibility predicates as false, claims anyway, and receives the non-audible fallback after one second. **Fix:** distinguish intentional suppression from a missing claimant, and enforce focused-thread suppression before any fallback grant. Add that case to R6-T22.

13. **Major — §14.3 omits the outcome-to-cue mapping.** Saying `received`/`done`/`failed` come from `ai.runFinished` does not preserve 03/04/05’s different predicates: visible assistant text, bot sessions, check-ins and ordinary routine runs. Arbitration only deduplicates identical cue IDs; wrongly emitting different cue kinds remains possible. **Fix:** define one shared notice-to-cue mapping and test every owner, outcome and `hasVisibleAssistantText` combination.

14. **Major — §§10.7/12.2 duplicate haptics across displays.** Every notch document presents the same attention and invokes `notch.haptic`; that procedure accepts only a pattern. Main cannot enforce “one per attention identity” across documents or reloads. **Fix:** include the permission lineage and question-step identity, and deduplicate centrally. Test simultaneous expansion on multiple displays.

15. **Major — §11.4 has no rendering path for connector asks.** It ranks `connector-ask`, but the route table and §12 define only permission descriptors for `/approval/$id`. ConnectorGate requests are separate from those descriptors and need their own response flow. **Fix:** specify an Open-in-app presentation for connector asks, or a complete connector card flow. Test a connector ask with no pending permission.

16. **Major — global question priority cannot be implemented with the stated inputs.** F5 says question descriptors are available only after loading a thread; §11.3 holds only the current and next threads. A question in a third waiting session remains unknown behind two unresolved approvals, contradicting `question > approval`. **Fix:** add a cross-thread classification summary, or explicitly revise the priority rule for unloaded sessions. Test three waiting threads.

17. **Major — §12.6 assumes every bot already has a forever session.** A newly created bot can have `sessionId: null`. The idle companion’s Message/Call action therefore has no ID for its reply route, and no specified chat-opening operation. **Fix:** define a click-owned `bots.openChat` operation, await its result and thread readiness, then navigate. Test a bot whose chat has never been opened.

18. **Major — §13.5 reads a field absent from the contract.** `setShape` contains `visible` and `audio`, but no `documentVisible`. Native visibility and actual document visibility are different facts. Furthermore, a last shape report can become stale when the Space changes without another shape change. **Fix:** add explicit visibility updates, clear them on navigation/destruction, and apply the conservative suppression flag to background-task notices too.

19. **Major — §10.10 adds an action to a coalescing stream.** Implemented `window.events` coalesces by `event.type`; multiple `{ type: "open" }` commands can replace one another. A destination-opening command is not a replaceable window-state level. **Fix:** give open commands lossless delivery with IDs and acknowledgment, or use a separate actionable procedure/stream. Test delayed consumption and renderer swapping.

20. **Major — §§10.2/10.6/15 provide no API for Try again.** After metrics failure or the readiness give-up threshold, Settings promises re-probing and restarting. The contract exposes only status and preview to main-window callers; neither performs recovery. **Fix:** add a main-only retry mutation that clears the relevant cache and failure budget and reconciles the windows.

21. **Major — §10.6 cannot preserve the old document by reloading its view.** Reloading the same `WebContentsView` replaces its document and closes its old port. Keeping the native window visible does not keep the old interactive renderer available until readiness. **Fix:** use a separately loaded replacement view with a readiness-controlled swap, or specify hiding and failure recovery during reload. Test delayed and failed replacement boot.

22. **Major — §12.5 ports dictation cancellation races into additional lifecycle paths.** The old hook’s cleanup cancels only an already-created recorder. A delayed permission/getUserMedia result can create a recorder after unmount; transcription can also deliver text after cancellation or a session change. **Fix:** add operation tokens, cancel late recorder acquisitions, discard stale transcripts and coordinate pipeline disposal with in-flight work. Extend R6-T21 with delayed acquisition and transcription.

23. **Major — §12.1’s exhaustive disclosure table still omits `sandbox_denied.note`.** `shared/agent-types.ts` defines it as what the command said it would do outside the workspace. An approval showing only the command and denials can conceal that additional explanation. **Fix:** display the note fully or make such requests Review-only; add a non-empty-note case to R6-T18.

24. **Major — R6-T18 does not verify the safety predicate’s actual geometry.** Its jsdom tests cannot establish real text wrapping, overflow or whether the complete question and controls fit the clamped body. Width checks alone also miss vertical clipping. **Fix:** add Electron/browser tests using actual fonts, translated text, multiline fields and the returned layout clamp; withhold acceptance whenever either dimension overflows.

25. **Minor — the remaining numerical provenance claim is still overstated.** Examples without stated derivation include the 250 ms reconcile debounce, 48 px taskbar reserve, retry intervals and 150 ms haptic threshold. The hatch’s `{ stiffness: 420, damping: 18 }` also is not a demonstrated conversion of “0.6 damping”; under unit mass its damping ratio is approximately 0.44. **Fix:** identify each independently chosen policy constant and its rationale or measurement source, and document the spring model instead of claiming an unsupported conversion.
