## Fix log

- **Codex #8: live goldens are equivalent to the spec's record-and-replay, and the recording is implemented anyway.** The spec's replay design derives the AG-UI golden from a recording of `NdjsonHost`'s pre-strip events. As built, the golden is derived from a live `AguiHost` run whose compat bytes are asserted equal to the pre-change baseline in the same test. `wire-record.integration.test.ts` closes the gap between the two: for five scenarios it records under `--wire ndjson`, shows the recording's `out` events serialise to exactly the baseline stdout, and shows the internal events the agui host's session hands the emitter are exactly the recorded ones (serialised at emission, as the recorder does: `tool_call_start.input` is a live object that the tool-timeouts extension later extends with `timeout`). The legacy half of the emitter's input is the compat stream, already byte-equal. So a replay of the recording feeds the emitter the stream the live run fed it; the live run additionally exercises the real host-session interplay (admission, tokens, settle) that a replaying fake session would have to re-enact.
- **Codex #8: how the new baselines are "pre-change".** `git archive d9cf445e` (the commit that recorded the first 14 baselines, before any `src` change) into a scratch tree, the current `__tests__/harness.ts`, `scenarios.ts` and `ndjson-golden.integration.test.ts` copied in, `RECORD_NDJSON_BASELINE=1` run once to write the 10 missing baselines, then three more runs to check they are deterministic on that host, then the 14 existing ones compared with this branch's (identical). The golden test now only reads baselines; the flag writes a missing file and never overwrites.
- **Codex #8, Claude #20: what the fake provider cannot drive.** pi 0.85 prepares sibling tool calls one after another: `executeToolCallsParallel` (`pi-agent-core/dist/agent-loop.js:326-345`) awaits each `prepareToolCall`, whose `beforeToolCall` is our gate, before any call executes. Two gate cards therefore never coexist, and "two parallel permissions resolved in reverse" needs asks raised by commands already running: `sandbox_denied`/`network_host`, which need an OS sandbox and its proxy. Those, `browser_task` (a browser) and `ppt`/`document` (main's host services) are covered by the real `AguiHost` over a scripted session and main's relay (`host-scripted.test.ts`) and by the emitter tests. Compaction's continuation needs ~250 KB of history to have something to summarise; the stall continuation exercises the same `continuePastRecoverableFailures` loop and a turn-origin site with a 30-line golden.
- **Codex #4: why the reservation is agui-only.** The legacy host lets a `send` that races an idle Stop or reset prompt the session being aborted, and then clears `busy` under it. Fixing that under `--wire ndjson` would change `--wire ndjson` output in that race, which this slice forbids. Under agui the compat stream therefore differs from ndjson only in that race (the racing message is queued with `waitingFor:"turn"` and runs after, instead of going into the aborting session); every golden, including `reset-mid-run` and `stop-then-message`, still matches byte for byte.
- **Codex #2: why not a run-scoped user message id.** Echoing under `${runId}:user` would give the sending ChatClient a second user message beside its optimistic one. Keeping the client's id and not echoing a known id again is idempotent for every processor that saw the first echo; only a respawned process lacks that knowledge, hence the main-side rule.
- **Codex #10: the guard, and what stays renderer-side.** `decideWhenBusy` calls a strategy synchronously inside `sendMessage` (`chat-client.ts:2277`, `:2355-2376`), so a throwing strategy rejects the send before anything is queued or delivered. Routing busy submissions to `ai.queue.enqueue` is the composer's branch in the chat kit; the agent side of it (legacy `enqueue` steering, parking, surviving Stop) is covered by the goldens and the host property test.
- **Codex #15, Claude #21: why one assertion stays.** `aguiEvent<T>` returns `Extract<Event, {type: T}>`; for a generic `T`, TypeScript cannot relate `{type: T} & EventPayloadOf<T> & {timestamp}` to that union member, so any single generic constructor needs an assertion, and per-type builders (21 functions) would only move it. Call sites stay cast-free and payloads are checked by `EventPayloadOf<T>`. The assertion is verified at runtime instead: `@ag-ui/core/schemas`' `EventSchemas` parses every event of all 24 goldens and one of every emitted type built through the emitter. `@ag-ui/core/schemas` is test-only, so the runtime still does not load zod.
- **Claude #10: settle on `ready`, not on `segments_cleared`.** `resetConversation` emits `ready` before `segments_cleared`. The sink now closes the cancelled run when a `ready` arrives while a reset is in flight (set by `beforeAbort("reset")`, cleared by `afterAbort`), and keeps the `segments_cleared` settle as a no-op backstop.
- **Hidden turns (found by the host property test).** A Stop or reset during bot housekeeping can land the hidden turn's closing bracket (its `finally`) after the next `RUN_STARTED`; the emitter would then drop that run's events as hidden. A run opening now forgets hidden depth: housekeeping runs inside `send()` with admission held, so no hidden turn is live when a run opens. Unit test in `emit.test`.
- **Claude #15 on Windows.** The pipe-or-socket check applies on POSIX only, where libuv and inherited descriptors share the numbering; on Windows a CRT descriptor the runtime did not open is not open, and libuv's `fstat` of a pipe handle is not relied on.
