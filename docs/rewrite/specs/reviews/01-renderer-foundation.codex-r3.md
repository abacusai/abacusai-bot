1. **Major — §6.7 claims skipping pop-up matches preserves `paneKey`.** On `/routines`, the deepest match is `_list.index`; on `/routines/new`, skipping `new` selects `_list`. The key still changes and remounts the background. The same problem affects connectors when its route is excluded only while `connector` is set. **Fix:** explicitly map each background/pop-up pair to one stable boundary key, using actual route IDs including groups and pathless layouts. Extend R1-T1 to connectors.

2. **Major — §§5.3/7.5 claim the drawer’s top is `toolbarHeight + 8`.** Registry `DrawerContent` retains `m-(--drawer-inset,0px)`. Setting both `--drawer-inset: 8px` and `top: toolbarHeight + 8px` puts the popup’s border box at `toolbarHeight + 16px`; the bottom gap likewise becomes 16px. **Fix:** account for the registry margin exactly once, either through positioning or a scoped margin override. Verify the full popup rectangle in both densities.

3. **Major — §7.4 prescribes `width: max(calc(…), min-content)`.** Bare intrinsic sizing keywords are invalid arguments to `max()`, so this declaration cannot implement the claimed alignment. Intrinsic calculations require the separate `calc-size()` mechanism. [CSS sizing specification](https://www.w3.org/TR/2026/WD-css-sizing-4-20260904/). **Fix:** use `width: calc(…)`, `min-width: min-content`, and explicit flex behavior. Calculate against the actual occupied sidebar width, including the 88px bots strip, and test declaration validity plus alignment.

4. **Major — §6.7 claims its type maps cover settings transitions.** `navTypesFor` emits `settings-in` and `settings-out`, but `PANE` maps neither, so the content pane resolves to `"none"` and cuts immediately. Only the new sidebar receives animation CSS. This omits the settings pane transition required by PLAN’s motion table. **Fix:** map both settings types for pane enter/exit and define their old/new CSS. Test rendered animations for entering and leaving Settings.

5. **Major — §6.7 gives history direction precedence over pop-up/search suppression.** Closing a masked sheet with `history.back()`, or traversing back between search-only entries, emits `nav-back` before reaching the rule that says these changes produce no type. Forward traversal can similarly reuse an inappropriate saved intent. **Fix:** suppress background-equivalent pop-up and search-only transitions before applying history direction or saved intent. Add back/forward cases to R1-T11 and R1-T11b.

6. **Major — §7.9 specifies the wrong Hotkeys provider and hint APIs.** In the cached `@tanstack/react-hotkeys@0.12.1` declarations, provider defaults are nested under `defaultOptions.hotkey`; `defaultOptions.platform` is invalid. `useHotkeyHint` returns a boolean indicating held-modifier visibility, not a formatted ⌘/Ctrl label. **Fix:** pass `{ hotkey: { platform: mappedPlatform } }` and use `formatForDisplay(binding, { platform })` for labels. Test provider defaults without explicit per-binding overrides.

7. **Major — §8.6 subscribes to transport closure only after boot.** A port can close after prefs finish loading while `changeLanguage()` is still awaited. The closure occurs before the listener exists, and the specified sequence never checks `transport.state`, leaving the mounted application attached to the cached dead client. **Fix:** register closure handling immediately after acquiring transport, check closed state before mounting, and define late-listener behavior. Test closure between successful prefs loading and router creation.

8. **Major — §15.5 omits an existing Transport implementation.** It adds required `state` and `onClose` members but requests implementation only in `createTransport` and `memory.ts`. `data/transport/websocket.ts` independently constructs a `Transport` and will no longer satisfy the interface. **Fix:** include WebSocket lifecycle handling, explicit closure, and exactly-once notification tests in the amendment.

9. **Major — §3.4 requires unsupported `no-restricted-syntax` configuration.** The installed oxlint schema and declarations contain no such rule; spec 00’s implementation notes explicitly record this limitation. Adding the prescribed rule blocks configuration validation. **Fix:** remove it and enforce forbidden member access through R1-T15’s AST checks, covering both `window.api` and `ipcRenderer`.
