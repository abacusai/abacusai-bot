1. **Major — F4 and §23.4 amend an obsolete contract.** The spec claims 04 defines `sessions.events` and proposes dropping `ai.runFinished`. **04 r3 already consumes 03 r3’s `ai.runFinished` unchanged**, with one subscription per document shared by bots and sessions (§26.4(e), §26.7). **Fix:** remove the rename amendment, update the cited revisions, and feed notch consumers from the existing shared subscription. Test all consumers against the same notice.

2. **Blocker — §6.3 cannot implement its resume table.** `resumeStep(stored: string | null)` must map new `"welcome"` to `welcome` but legacy `"welcome"` to `connected`. Its input contains no discriminator. Leaf provenance does not solve this unless the migration or API exposes and uses it. **Fix:** canonicalize legacy values during migration, or persist a flow version. Test identical strings from legacy import and renderer-next writes separately.

3. **Blocker — §§5.1/6.2 reject an active sign-in.** Every `$step` navigation runs `guardStep`, but `connect` redirects to `welcome`; the guard receives no pending-attempt information. Consequently, the welcome click starts authentication and then navigates to a route its guard rejects. **Fix:** distinguish cold resume from an active, identified authentication attempt. Add a real-router test covering welcome click, pending authentication, cancellation, and restart.

4. **Major — §6.4 has undefined and racing transitions.** “Skip for now” dispatches `skip` from `connect`, but §6.1 defines that transition only from `welcome`. The table also uses `tour`, which is absent from `FlowEvent`. Cancellation/restart lacks an attempt token, so an old `auth-cancelled` or `auth-ok` result can overwrite a newer attempt or skipped step. **Fix:** complete the event union/table and ignore outcomes from superseded attempts. Test delayed cancellation and restart results.

5. **Major — §5.1 contradicts the permitted no-model path.** Its example redirects `first-bot` without model access to `models`, while §7.5 explicitly allows continuing with no credentials or local model. That guard also requires information absent from `FlowFacts`. **Fix:** remove the model prerequisite or record an explicit changed decision with a usable exit. Test Skip → models Continue → connectors Continue with no model configured.

6. **Major — §6.5’s completion is only partially failure-safe.** `account.skipOnboarding()` commits `onboarded: true` before the awaited prefs write. If that second write fails—or the app quits between writes—the onboarding gate prevents returning to the completion step, and the selected chat/tour/pairing target is lost. R6-T6 tests only failure of the first call. **Fix:** make completion resumable/idempotent, or make cleanup nonblocking after the account commit. Test every failure and interruption boundary.

7. **Major — §§8.3/23.3 introduce an unspecified automatic schedule and orphan it on cancellation.** The current Chief of Staff template has no check-in field; old first-bot creation creates only a bot, and its editor defaults check-ins to Off. The amendment nevertheless creates “the template’s check-in.” Moreover, 03 deliberately leaves a deleted bot’s check-in running as an ordinary routine. **Fix:** retain Off unless a changed decision explicitly authorizes a schedule. If onboarding creates a routine, track and remove it on cancellation and handle partial creation failures.

8. **Major — §8.1’s “once per document” storage lacks an in-flight state.** The store holds only `{ botId }` or `{ skipped }`, both available after asynchronous creation. A remount before persistence completes can start another creation; the old implementation sets `startedRef` before starting the mutation. **Fix:** synchronously store a pending promise/stable creation ID and share it across mounts. Extend R6-T9 with delayed persistence and remount/Strict Mode cases.

9. **Major — OB11/§7.5 drop environment-configured provider detection.** The proposed loader reads `settings.keys.listProviders`; the old `ProviderSetupStep.refresh()` combines stored providers with `models.some(m => m.configured)` specifically because environment keys count. Existing environment-backed OpenRouter/Gemini access can therefore appear disconnected. **Fix:** preserve the configured-model plus stored-key calculation. Test environment-only credentials and removal of a stored key while environment access remains.

10. **Major — OB12 incorrectly marks Discord coverage as parity.** The old offered list includes `messaging-discord`. The new twelve-tile grid excludes it, and “Many more” includes only `kind: "platform"`, which cannot recover that messaging connector. No retirement decision accounts for the omission. **Fix:** include Discord in the grid or another reachable onboarding list, or explicitly record the behavior change. Test reachability of every formerly offered connector.

11. **Major — §7.6 cannot obtain its pairing behavior from 05’s exported API.** `useConnectFlow().start(id)` in **05 r2 §12.4** enables messaging and then navigates to Library. Its API provides no navigation policy or pairing callback. Merely saying onboarding queues pairing cannot prevent that navigation. The ephemeral queue also disappears on restart. **Fix:** amend 05 with an explicit pairing/navigation policy, define persistence and draining of multiple queued platforms, and resolve precedence against Edit/Message/tour completion targets.

12. **Major — §16 reinstates superseded route-transition mechanics.** It assigns onboarding route changes and cross-route avatar flights to React `<ViewTransition>`. **01 r4’s implementation amendment explicitly says React cannot start/join those router commits**; route transitions use the router’s document transition and shared CSS names. **Fix:** use the implemented navigation-intent mechanism and `useSharedElementName`; reserve React transitions for changes within a route. Extend the real-browser single-transition test through onboarding and notch navigation.

13. **Major — §11.3’s two-stream bound is false.** Loading only the current and next thread does not limit subscriptions to two. **02 §10 keeps unmounted clients subscribed until eviction from its eight-entry LRU.** Visiting successive approvals therefore accumulates live streams. Releasing a pin in R6-T19 does not close them. **Fix:** configure a two-thread runtime budget or explicitly retire obsolete notch sessions. Count open iterators after twenty sequential presentations.

14. **Major — §§11.1–11.4 omit data required for bot attribution.** The notch boots with sessions, bots and prefs, but check-in runs have `owner: null` and require a `routineId` join. Ordinary routine runs also require `RoutineRow.botId` to apply per-bot settings. Routines load only when quick actions open. **Fix:** preload/synchronize routines for attention, attribution and sound filtering. Test ownerless check-in and ordinary routine runs under per-bot `nothing` and `needs-me`.

15. **Major — §11.6’s hover lock can lock itself indefinitely.** An approval expands automatically, and “body is expanded” alone locks its identity. When the descriptor resolves, the next identity queues despite §12.1 promising immediate advancement. Main-focus calm, quiet hours and snoozing can similarly queue behind the displayed approval. **Fix:** distinguish automatic expansion from user interaction, and always invalidate resolved, expired or snoozed attention. Test external answers and quiet/focus changes with the pointer stationary.

16. **Major — §§5.4/11.6 assume a timeout and cancellation guarantee the chat kit does not provide.** The kit’s five-second limit applies to replay readiness after hydration, not the entire `load()` operation. The director also specifies no generation check across awaited loads and shape changes, allowing an obsolete presentation to navigate after newer attention or calm state wins. **Fix:** define a total presentation deadline and cancellation/generation checks after each await. Test stalled hydration and out-of-order completions.

17. **Blocker — §10.1 never sizes the `WebContentsView`.** Adding it to `win.contentView` does not establish full-window bounds. Subsequent `win.setBounds()` calls also do not specify child resizing. The existing `RendererHost.#fit()` explicitly calls `view.setBounds()`. **Fix:** size the view initially and on every native bounds change, before resolving growth. Verify rendered viewport dimensions across grow, shrink and display changes. [Electron’s example explicitly sizes child views.](https://www.electronjs.org/docs/latest/api/base-window)

18. **Major — §10.6 destroys native windows without specifying WebContents disposal.** Closing a `BaseWindow` does **not** automatically destroy its attached view’s WebContents. Disable, unplug, startup failure and retry can leave renderers, RPC streams and Whisper allocations alive. **Fix:** explicitly close each view’s WebContents on every disposal path and make cleanup idempotent. Test repeated enable/disable and retry cycles using live WebContents/iterator counts. [Electron documents this ownership requirement.](https://www.electronjs.org/docs/latest/api/base-window#resource-management)

19. **Major — §14.2 does not guarantee one sound owner.** `"main" | "notch"` identifies a class of documents: with extra displays, every unlocked notch document matches `"notch"` and can play. Publishing ownership “in one main tick” also cannot atomically update separate IPC consumers; opposing stale values can permit duplicate playback. **Fix:** select a specific WebContents and arbitrate each cue centrally by event ID. Test multiple unlocked displays and reordered ownership/event deliveries.

20. **Major — §14.3 watches the selected presentation instead of all attention.** A second session can enter `waiting_permission` while another critical item holds the presentation, producing no selected-presentation transition and no `needs-you` cue. Connector asks are also omitted from its trigger list, although 03/04 include them. **Fix:** use the shared session-transition and connector-ask watchers independently of presentation selection, then apply owner and preference gates. Test attention arriving while another approval is locked.

21. **Major — §§10.4/13 assume full-screen visibility knowledge the controller never acquires.** Display geometry events do not report another app’s Space transitions, and the controller lists no foreground-Space observer. Readiness or `isVisible()` does not establish that the user can see the companion. Dropping banners on that assumption can hide attention; reply notices can expire during a long full-screen stay despite “nothing is lost.” **Fix:** use conservative banner fallback or verified visibility tracking, and define hidden-state retention. Test another app’s full-screen Space with compositor-level evidence.

22. **Major — §§12.1/23.2 leave the approval safety predicate undefined.** `permissionSummary(d).complete` gets no exhaustive definition. A short command alone is insufficient when its request includes `cwd`, credential paths or sandbox denials; short URLs can differ in omitted paths. §12.2’s option-count rule likewise does not ensure question labels/descriptions fit. **Fix:** define required visible fields per request variant, default unsupported/truncated requests to Review, and test every variant, credential warning, ambiguous path/URL and oversized question.

23. **Minor — §10.5’s shortcut can target a nonexistent window.** It selects the display nearest the cursor, but default macOS configuration creates only one targeted display, and Windows creates only the primary capsule. A cursor on another monitor has no corresponding notch window. **Fix:** choose among existing ready windows, with an explicit fallback when the nearest display has none. Test secondary-monitor cursors with extra displays disabled and on Windows.

24. **Minor — §10.2/R6-T24 describe AppKit struct values as `nil`.** `auxiliaryTopLeftArea` and `auxiliaryTopRightArea` are **`NSRect` values**, empty when unavailable on a screen; they are not nullable objects. Before macOS 12 the selectors are unavailable. The JXA approach is plausible, but the proposed fixtures encode the wrong bridge behavior. **Fix:** check selector availability, extract struct fields, distinguish zero-area success from probe failure, and test the actual JXA output shape. The local SDK’s `NSScreen.h` declares all three APIs available since macOS 12.

25. **Major — the requested “no code idea copied” condition is not met.** The spec explicitly adopts clone-derived implementation recipes: §10.2’s inference constants and 700 ms delayed shrink, §10.7’s persistent stdin-driven JXA haptic helper with a 300 ms throttle, and §11.6’s hover timings. These correspond to the inspected `openbot-run` source. Re-expression does not make their provenance independent. **Fix:** derive these choices independently from official APIs, canvas requirements and hardware measurements, and remove the clone-derived recipes—or explicitly amend the provenance requirement. This finding does not assert that copyright protects ideas.
