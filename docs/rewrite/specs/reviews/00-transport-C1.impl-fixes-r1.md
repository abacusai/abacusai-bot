## Rebuttals and partial fixes

- **L17 "`subtask-edges` golden asserts `finished` for a bracket its fixture calls 'Left open by a crash'".** Kept, with evidence. In that fixture, `sub-open` is followed by the user text `u2` and then by `created sub-trailing`. The old UI (`hydration.ts:28-29`) keeps `sub-open` open across the user text and closes it as a **hand-back** (completed) at `sub-trailing`. Under the new provisional rule the mapper does the same, so `finished` is old-UI parity. The fixture's description refers to the crash that left the frame without a close, not to the displayed outcome. `late-close-interrupted` now covers a bracket that nothing settles, which ends as `error: interrupted`.
- **L10 "stable under append only" (positional `segment-<i>` and `#n` suffixes can move when the old renderer rewrites a file with earlier segments removed).** Partly addressed. `#n` is now assigned per base id, so only a repeated id can move. A segment without its own id has no stable name to derive from; this is a limit of the data. The other half of the finding, `ai.hydrate` answering an unknown `before` cursor with the newest page (`rpc/procedures/ai.ts`), is **handed over** to the relay/RPC owner. It should return an empty page or `BAD_REQUEST`.
- **L12 "nothing is dropped".** Fixed for keys (`extra`). `isSpinny` is read and dropped on purpose, and the header says so.
- **L16 credits inside brackets.** Not moved. They stay in the child message's `metadata.abacus.credits`, and the old UI hid them too. It is listed in the §14 request below so the kit decides.
- **Feedback before the first user message.** The old UI computes `2 × 0 − 1 = −1` for a bot text before any user message. The mapper gives it no row: an index of −1 is not a backend message.
- **User text inside a bracket.** The old UI tags the bracket's later segments into it and hides them from the main thread. The mapper still maps them into the top-level assistant message after the user message. That is deliberate and unchanged: the reviewer marked it better than the old UI.

## §14 amendment request (spec 02, renderer side)

1. **User messages** (§5.3): the text is shown through `visibleUserText` (strips `<system_reminder>`). 3. **`web_search_results` and `media`** (§5.3): the old UI never rendered them (`render-utils.ts` has no case). Decide explicitly whether migrated history shows them for the first time or hides them. The mapper keeps both either way.
4. **Credits inside a bracket**: the child message's `metadata.abacus.credits` are not in the §5.3 footer, which reads top-level messages only. The old UI hid them too. State whether the sub-agent card shows them.
5. **Tool data** (§5.4a): the migrated normalisation reads `expandToolResultData(result)` instead of `result.metadata.abacus.data`. Migrated calls have no `input` and no `output` (read `parsePartialJSON(arguments)` and `result.content`). `metadata.abacus.synthesised: true` marks a synthesised result.
