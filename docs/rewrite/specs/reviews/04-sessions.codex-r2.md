1. **Major.** §11.4 says intercepted dock chords return `false`, while ordinary keys return `true`. Ghostty 0.4.0 implements the reverse: a truthy handler result prevents default and skips encoding. This suppresses ordinary terminal input and lets intercepted chords reach the shell. [Installed implementation](/Users/rajaniraiyn/work/abacusai-bot/node_modules/ghostty-web/dist/ghostty-web.js:853). **Fix:** return `true` for handled keys and `false` otherwise, composing dock interception with the existing copy/paste/scroll handler. R4-T39 must also test ordinary printable input.

2. **Major.** §§6.1, 26.4(e), and R4-T38 publish the shared completion notice from compat taps at turn end. This contradicts **03-bots r3 §24.11**, which requires `ai.runFinished` at the relay's authoritative, first-terminal-wins boundary. Compat `turn_complete` fires between tool rounds and cannot cover all main-synthesized failures. The nullable run ID also undermines deduplication. [Bot requirement](/Users/rajaniraiyn/work/abacusai-bot/docs/rewrite/specs/03-bots.md:1115), [relay terminal handling](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/agui/thread-relay.ts:254). **Fix:** consume the same `ai.runFinished` contract as bots, including event-ID resume and background-wire coverage. Replace R4-T38 with multi-round, crash, timeout, cancellation, and reconnect cases.

3. **Major.** §8.6 claims persisted stages prevent repeating creation side effects. Reloading after worktree creation/attachment but before persisting `checkout-ready` still repeats `materialize`. Main generates a random branch/path on every call and has no idempotency guard. Choosing “No worktree” afterward is also a no-op, leaving any already-attached worktree selected. [Materialization](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/service-host.ts:2971), [random worktree identity](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/workspace/git-service.ts:524). **Fix:** make materialization idempotent by persisted operation/session identity, reconcile the attached worktree before retrying, and explicitly detach for “No worktree.” Test reload after server success but before the stage write.

4. **Major.** §26.4(b) introduces checkout-keyed git rows, but §6.2 and R4-T6 still select `useGitState` by workspace. Multiple worktrees within one workspace therefore remain ambiguous. Both implemented collection and feed keys also use `workspaceId`. [Renderer key](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer-next/data/db/tables.ts:282), [main key](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/rpc/tables/index.ts:169). **Fix:** define `useGitState(checkout)`, expose an authoritative checkout key, and amend both key functions. Test simultaneous primary-checkout and two-worktree rows, including sidebar chips and Files decorations.

5. **Major.** §§14.4 and 26.4(b) fingerprint existing files only from worktree bytes. A staged patch can change while worktree bytes, status, and addition/deletion counts remain unchanged. HEAD changes can likewise alter a diff without changing those bytes. `sameGitState` then sees no change, preserving stale diffs and Keep marks. [Equality implementation](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/rpc/tables/git-state.ts:32). **Fix:** fingerprint the actual reviewed change, including HEAD, index, worktree, and scope as applicable. Extend R4-T25/R4-T33 with same-stat index-only and base-revision changes.

6. **Major.** §§14.1–14.5 show Staged/Changes sections but never define how selection supplies `scope`; `DiffSearch` cannot preserve it. Main defaults to `unstaged`, and its empty-diff fallback diffs the file against nothing. A staged-only tracked modification can therefore appear as an entirely added file. [Diff implementation](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/workspace/git-service.ts:683). **Fix:** carry scope through selection, query keys, and full-diff navigation; define the merged view explicitly. Restrict all-added fallback to confirmed untracked files. Test staged-only and mixed staged/unstaged files through reload.

7. **Major.** §14.4 promises “New files are moved to the Trash,” but §26.4(c) sends staged additions through `git restore --source=HEAD --staged --worktree`. Git removes tracked paths absent from the restore source, bypassing Trash. [Git documentation](https://git-scm.com/docs/git-restore/2.25.0). **Fix:** detect paths absent from HEAD, preserve their contents through Trash before removing index entries, and define rename handling using both source and destination paths. Add staged-addition and staged-rename tests; current R4-T25 covers only untracked Trash.

8. **Major.** §§6.1 and 17.2 check only `workspaces.checkPath`, although the effective session checkout can be a sibling worktree. That procedure checks the primary workspace path. A deleted worktree can leave Send enabled, then produce a missing-folder recovery action that relocates the wrong folder. [Path check](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/workspace/workspace-service.ts:196). **Fix:** add checkout-aware existence/status and distinguish missing-worktree recovery from workspace relocation. Test a missing worktree with an intact primary checkout.

9. **Major.** §9.2 runs startup “once per mount” and switches conversations only after the first successful start in the document. S42/S43 claim parity with startup recovery and restoration per CLI start. The old renderer reacts to subsequent stopped/error transitions while the route remains mounted. [Old startup effect](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer/components/chat/chat-panel.tsx:1046). **Fix:** scope startup/recovery and restoration to process incarnation, cancel stale retries, and await joined startup readiness. Test a crash and restart without route unmount, including a second incarnation in the same document.

10. **Major.** §9.3 and R4-T35 describe connection success followed immediately by `connectors.respond("connected")`. **03-bots r3 §11.4** requires awaiting MCP refresh for the requesting session first, with refresh failures leaving the card actionable. Otherwise the released agent can call a tool absent from its current tool list. [Shared-card requirement](/Users/rajaniraiyn/work/abacusai-bot/docs/rewrite/specs/03-bots.md:776). **Fix:** make the r3 shared-card sequence authoritative here and test refresh-before-response, refresh failure, cancelled flows, and requests from a non-active workspace.

11. **Major.** §6.1 subscribes to background connector asks “for attention,” but §6.6's function accepts no connector requests and derives `needs-you` solely from `waiting_permission`. ConnectorGate emits requests without changing that turn phase, so a suspended session can remain labelled “running” and never enter SessionsNeedsYou. [Gate wiring](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/service-host.ts:793). **Fix:** include pending connector asks in session attention and needs-you cues, as bots do. Test an uncached background session whose turn remains streaming while awaiting a connector.

12. **Major.** §12.2 serializes ownership changes as capture → hide → present, without defining failure recovery or revalidation after awaits. Capture can reject, and closing/rematerializing a tab invalidates its lease while capture is pending. A rejected chain can block later ownership changes; a stale successful chain can present an inactive or occluded candidate. [Capture and close](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/browser/electron-browser-runtime.ts:340). **Fix:** recover the promise chain after failures and recheck candidate registration, lease generation, visibility, and occlusion before presentation. Extend R4-T18/R4-T30 with delayed capture followed by close, profile replacement, and an intersecting overlay.

13. **Major.** §§10.3–10.4 clamp chat width assuming the dock needs only 360 px, while a two-column dock requires at least 480 px plus its separator. Below `xl`, retaining a pinned sidebar can also leave less than 480 px for those columns. The leaf-count limits do not prevent this invalid layout. **Fix:** compute minimum dimensions recursively from the dock tree, use them when clamping chat width, and define folding when the tree no longer fits. Test existing multi-leaf layouts through 1440 → 1100 → 800 resizing with the sidebar pinned.

Add keyless URL and file cases to R4-T36.
