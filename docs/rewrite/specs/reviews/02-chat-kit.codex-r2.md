1. **Blocker. §3.3 initializes `reconstructCursor = activeRun.startSeq`, then drops `seq ≤ reconstructCursor`.** This skips `RUN_STARTED`. The snapshot also initializes `runs.active` empty, so a restored run never becomes active in either the store or ChatClient’s shared lifecycle. R2-T3 explicitly tests the incorrect exclusive interval. **Fix:** initialize to `startSeq - 1`, replay the inclusive interval, and assert restored busy state, Stop targeting and `sessionGenerating` before any content arrives.

2. **Blocker. §§3.4/4.6 claim throwing `AbortError` leaves run A untouched.** Before calling the adapter’s `send`, [`streamResponse()` resets the processor](/Users/rajaniraiyn/work/abacusai-bot/node_modules/@tanstack/ai-client/src/chat-client.ts:2551). The busy strategy does not protect a subscription-only run because `isSendBusy()` excludes `sessionGenerating`. I reproduced A streaming partial tool arguments, B receiving the proposed queued `AbortError`, and A’s subsequent arguments disappearing. **Fix:** isolate admission from the subscription processor, or prevent request setup from resetting another run’s processor. Extend R2-T20 with partial arguments and reasoning, rather than checking only retained messages.

3. **Major. §§3.2/9.2 claim `load()` makes the active transcript available before navigation commits.** Its promise resolves after snapshot application and client construction, before active-run reconstruction. Every active-run message is excluded from that snapshot. A thread containing only its first active run therefore mounts an empty log; a longer thread initially scrolls to the previous completed reply. The stated “already in flight … returns at once” rule also lets another caller bypass loading. **Fix:** return the existing loading promise and resolve readiness only after the client has consumed replay through checkpoint N. Test a delayed join with an empty completed transcript.

4. **Major. §3.3 says omitted activity is rebuilt from replay, but §4.2 prevents that reconstruction.** `agent.status`, `agent.heartbeat`, `agent.notification` and non-terminal `agent.error` are session-scoped and skipped at `seq ≤ N`. Neither activity nor notices appear in `ThreadSnapshot`. Reload loses tool counts, status and actionable notices, including notices emitted outside the active run. **Fix:** snapshot those session-scoped fields, or explicitly partition their reconstruction rules. Test hydration while no further heartbeat or notification arrives.

5. **Major. §3.4 applies store events and advances the reconstruction cursor before pushing them to ChatClient.** The pump can outrun the consumer; [`consumeSubscription()` deliberately yields to the host](/Users/rajaniraiyn/work/abacusai-bot/node_modules/@tanstack/ai-client/src/chat-client.ts:1942). Thus the store can report a terminal while the transcript still lacks its final tools/messages. The specified terminal calculations for steps and `afterMessageId` can use incomplete client state, and “reconstructed” means enqueued rather than processed. **Fix:** distinguish received and applied positions. Apply dependent store updates and acknowledge reconstruction in the consumer’s processing order. Test a buffered replay crossing the client’s processing budget.

6. **Major. §§3.3/3.5 leave old-client callbacks able to overwrite the new host binding.** The old client is unsubscribed/disposed after the new one becomes ready, while every client’s callbacks write into the shared `hostStore`. `unsubscribe()` synchronously emits loading, subscription, generation and connection changes. Without callback generation guards, old teardown can mark the new client disconnected or overwrite its state; delayed send acknowledgements create the same problem. **Fix:** guard every callback and asynchronous completion by generation, and keep staging-generation state private until the atomic swap. Extend R2-T2 with old teardown and delayed acknowledgements after the swap.

7. **Major. §10’s older-page request has no generation or reset guard.** It awaits `ai.hydrate`, then prepends into the client without checking whether recovery or `session.cleared` occurred meanwhile. A page requested before reset can restore deleted history; an old-generation result can modify the replacement client. **Fix:** capture generation, client identity and transcript reset revision; discard stale page results and deduplicate IDs. Test paging concurrently with reset and resync.

8. **Major. §10 prepends older messages but never merges their `abacus.runOutcomes`.** §14.1 explicitly pages outcomes alongside messages, and §5.1 renders historical terminal markers from those records. Older errors and cancellations therefore lose their markers when their message page is loaded. **Fix:** merge page outcomes by `runId` with the messages and define retention for their anchors. Add a paging test containing an older failed and cancelled run.

9. **Major. §5.4a recognizes live tools only when `call.output` contains a string `text`.** A running tool has no result/output yet, precisely when `live.output` and `live.display` must render. It satisfies neither the live nor migrated detection row. The normalization contract therefore cannot produce the promised live bash tail or pre-result diff. **Fix:** classify origin independently of result availability and normalize live display/output before a result exists. Test actual emitter calls with `output === undefined`, streamed output and successive display patches.

10. **Minor. §5.3 adds `VideoView`, but §5.1 never registers it.** The configured `partsComponents` omits `video`. The ai-react dispatcher selects the `video` key and falls back to `UnknownPart`, which renders nothing in production. **Fix:** register `video: VideoView` in both skins and make R2-T11 exercise the exported configurations.

11. **Major. §§3.3/10 assume replayed message IDs cannot collide with completed history across process replacement.** The emitter initializes `steerCount` to zero, and [`steerMessageId()` produces only `steer-N`](/Users/rajaniraiyn/work/abacusai-bot/packages/agent/src/agui/ids.ts:19). After respawn, a new `steer-1` collides with persisted `steer-1`. I reproduced the installed processor replacing the old steering text with the new text. Extending queue identity with incarnation does not protect transcript identity. **Fix:** namespace steering IDs by run or incarnation. Test persisted steering history followed by a replacement process and another steer.

12. **Minor. §10’s “at most 300 messages” claim and R2-T31 fallback do not cover the unbounded cases.** Trimming is deferred while reading history, and active-run replay is never trimmed. A replayed run can exceed the bound outright; a single message can contain arbitrarily many tool parts. Lowering `MAX_MOUNTED` cannot fix those cases. **Fix:** define a mounted-row/part budget independent of processor retention and make the fallback address active replay. Benchmark runs exceeding 300 messages and large single-message tool loops.

13. **Minor. §§3.4/3.5 cannot report a healthy idle subscription as connected.** The pump discards `abacus.subscribed`, while ChatClient sets `connectionStatus = "connected"` only when it processes a chunk. A hydrated, idle thread with no subsequent event remains `"connecting"` indefinitely. Pump-managed reconnects likewise do not naturally update the client’s connection lifecycle. **Fix:** derive transport connection state from the subscription barrier and pump lifecycle, separately from ChatClient’s chunk-driven state. Test an idle subscription and reconnect with no following AG-UI event.
