1. **blocker — A.1 imports nonexistent TanStack AI exports.** The spec re-exports `ChatHydrationResult` and `RunAgentInputContext` from `@tanstack/ai`. In the reference clone, both are declared in `ai-client/src/connection-adapters.ts`; only `RunAgentInputContext` is exported from the ai-client root. **Fix:** import the latter from `@tanstack/ai-client`, derive the hydration type from `SubscribeConnectionAdapter["hydrate"]`, and add compile-time checks for every named library import.

2. **major — A.4.4/A.12 contradict “one port per page load.”** The preload creates a new channel for every request, while the renderer retries after 250 ms. A delayed first response allows both requests to create ports. The unused response port has no specified cleanup. **Fix:** deduplicate pending requests, close rejected or late response ports, and test delayed responses and retries in real Electron.

3. **minor — A.4.2 accumulates lifecycle listeners.** Every connection adds another persistent `did-start-navigation` listener and another `destroyed` listener to the same `webContents`. Reloads retain those listeners. **Fix:** install lifecycle listeners once when registering the contents, remove closed ports from the registry, and unregister contents on destruction.

4. **major — A.4.2 overstates swap readiness.** It claims subscriptions are live before the flip because `window.ready` resolves `rendererReady`. Existing readiness means the first React commit, and `renderer-host.ts` proceeds after a five-second timeout anyway. Neither establishes that asynchronous subscriptions or collection snapshots are ready. **Fix:** define a subscription readiness barrier and an explicit timeout policy; test slow initialization and aborted candidates.

5. **major — A.4.3 treats irreversible events as advisory notices.** Domain iterators use a bounded publisher queue and filter afterward. Terminal bytes, terminal exit, and permission requests can therefore be dropped among unrelated IPC traffic. Refetching cannot reconstruct terminal bytes. The tagged oRPC implementation also drops silently, providing no overflow notification for the promised log. **Fix:** filter before buffering, provide lossless delivery for terminal output, and define recovery for actionable events. [oRPC 1.15.4 source](https://raw.githubusercontent.com/middleapi/orpc/v1.15.4/packages/shared/src/event-publisher.ts).

6. **minor — A.2 gives credentials invalidation two different destinations.** `listStoredKeyProviders` says `system.events` invalidates it; A.2.3 routes `credentials-changed` to `settings.events`. Implementing either table literally leaves the other consumer stale. **Fix:** choose one destination and test credential save/removal against the query invalidation.

7. **major — B.3 equates committing with applying.** It calls `commit()`, advances `lastSeq`, and resolves echo waiters immediately. The DB clone’s `SyncConfig.commit` returns `true` or a receipt; ordinary commits can remain buffered while a user transaction is persisting. Simply awaiting the receipt would create a dependency cycle with the mutation’s echo wait. **Fix:** define received versus applied sequences explicitly, use the supported immediate transaction mechanism where actual application is required, and test server-normalized rows during optimistic mutations.

8. **major — B.3 can remain in error after recovery.** Initial failure calls `markError`, but reconnect/resync uses `initial: false`, which never calls `markReady`. The DB lifecycle requires `markReady()` to transition an errored collection back to ready. **Fix:** call it after the first successful usable snapshot, including recovery; replace the “exactly once” test with failure-then-recovery coverage.

9. **major — B.3/B.4 freeze after queue overflow.** The server yields `reset` and ends the stream. The client resnapshots on `reset`, but only reopens streams that *throw*. Normal completion leaves a current snapshot with no future changes. **Fix:** reopen on unexpected EOF as well as errors, and test a mutation after overflow recovery.

10. **major — B.3 filters buffered batches before checking their epoch.** Snapshot flushing drops every batch with `seq <= lastSeq`. Sequence numbers are comparable only within an epoch, so a different-epoch batch can disappear without triggering reset. Old connection batches can also contaminate a replacement stream. **Fix:** check epoch before sequence comparisons, tag buffers and snapshots with connection generations, and scope mutation waiters to `{epoch, seq}`.

11. **major — B.2 removes the memory stale-click guard.** The new delete request contains only `id`; main uses the row’s *current* `index` and `entry`. For duplicate entries, removing the first renumbers the second into the first ID. A stale click can delete that successor, whereas the existing request’s original index would reject. **Fix:** transmit the clicked row’s original index and entry, validate them under the store lock, and test duplicate-entry races.

12. **major — `listBotMemories` has incomplete parity.** B.2’s entry rows cannot represent `BotMemoryView.noteDays` or bots with empty memory. Watching `bots/<id>/` non-recursively also misses new daily files inside `memory/`. **Fix:** retain a bot-memory summary query/table and watch the daily-note directory, including directory creation and bot removal.

13. **major — `bots.chatPreviews` loses its refresh trigger.** A.2 says previews invalidate on bot/session row changes. Existing transcript persistence emits `bots-updated` without changing either row. The diff feed publishes nothing, so the new preview query remains stale after a saved reply. **Fix:** preserve a transcript/preview invalidation event independently of row diffs; test a save that changes only transcript content.

14. **major — A.3 does not specify the required hydration state.** `ChatHydrationResult` requires `activeRun` and `interrupts`; the described implementation only reads stored messages. The ai-client clone uses these fields to rejoin active work and restore pending approvals. **Fix:** combine persisted messages with authoritative live run and interrupt state, and test reload during generation and approval.

15. **major — C.3 does not preserve IDs “everywhere.”** Assistant grouping retains only the first segment ID. Text/thinking parts lose subsequent IDs, credits lose their IDs, tool parts use `toolCall.id` instead of the segment ID, and flattened groups lose their container ID. C-T2 consequently cannot pass as specified. **Fix:** preserve segment identities and timestamps in explicit metadata, retain group provenance, and define message boundaries that preserve edit/version targets.

16. **major — C.3 misclassifies older completed subtasks.** Its status expression requires `outcome === "completed"`. Existing hydration explicitly treats a completed frame with no outcome as completed, so older successful subtasks become errors. **Fix:** default a present completed frame’s missing outcome to `"completed"`; add a historical fixture.

17. **major — C.3 omits the existing subtask hand-back rule.** Existing hydration closes the previous bracket when another `created` frame arrives. The spec only describes matching created/completed brackets, leaving consecutive starts ambiguous and risking incorrect membership. **Fix:** specify the same positional state machine, including consecutive starts, unmatched closes, and trailing open brackets.

18. **major — C.3 can emit successful results for cancelled or denied tools.** Result state depends only on `toolResult.error`; a rejection without that field receives `state: "complete"` alongside `outcome: "denied"` or `"cancelled"`. The AI clone explicitly requires those outcomes to remain in the error state. **Fix:** derive result state from rejection/status as well as error, including synthesized results, and test these combinations.

19. **major — C.6 dual-writes creation but omits deletion.** `TranscriptService.remove` is used by conversation reset and session/workspace deletion. The spec adds v2 writes but no v2 removal. `ai.hydrate` then prefers the surviving thread file and can resurrect cleared history. **Fix:** remove corresponding v2 files through every existing transcript removal path; test reset and deletion through both interfaces.

20. **major — A.3/C.3 cannot repair an existing stale v2 file.** Hydration falls back only when v2 is missing. If v1 persistence succeeds and the subsequent dual-write fails, v2 exists with older content; the recorded migration will not run again. **Fix:** compare source timestamps during hydration, repair stale v1-derived twins, and isolate dual-write failures so the existing `onPersist` callback still executes.

21. **major — B.8’s prefs-drift justification is false.** Users need not run both renderers simultaneously. PR C migrates prefs while the old renderer remains active until Phase 7; subsequent legacy preference changes are absent from the eventual new renderer. **Fix:** synchronize durable keys during transition or perform a provenance-aware final import at cut-over.

22. **major — C.4 violates “existing fields win.”** Filling fields that equal defaults overwrites deliberately selected defaults. For example, an existing explicit `"system"` theme can be replaced with the legacy `"dark"` value. Default equality does not establish absence. **Fix:** merge by field presence or stored provenance, with tests for explicitly chosen default values.

23. **major — C.1/C.3/C.4 misclassify overwrites and rollback.** Steps 1–2 are called non-destructive because they create new files, yet they also replace existing v2 threads and prefs. A failed multi-file commit leaves earlier replacements installed; deleting staging does not roll those replacements back. **Fix:** distinguish creation from replacement, protect replaced destinations, and specify partial-commit recovery honestly. Test failure after a rename and before record persistence.

24. **major — C.5’s transcript archive gate cannot handle its own output types.** It requires every twin to have a newer/equal `source.updatedAt`, but `source.kind: "agui"` has no such field. Intentionally skipped corrupt/non-v1 files also never receive twins, preventing the whole-directory archive indefinitely. **Fix:** define verification separately for AG-UI-owned threads and define an explicit quarantine/retention policy for skipped sources.
