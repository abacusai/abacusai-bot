1. **Blocker — §§3.3–3.5 require methods unavailable through `useChat`.** The spec binds `chat.setMessagesManually` and calls `client.detach()`, `attach()`, `subscribe()` and `getMessages()`, but the hook keeps its `ChatClient` private and returns **`setMessages`**, not `setMessagesManually`. The lifecycle sketches cannot be implemented through the specified binding. **Fix:** explicitly own a `ChatClient` and expose a React subscription wrapper compatible with `ChatUIHost`, or provide another concrete recovery mechanism using the hook’s public API. Type-check the complete binding against ai-react 0.29.3.

2. **Blocker — §3.3 omits the UIMessage-to-AG-UI input conversion.** `ai.send` accepts messages containing `parts`; the agent’s [`newestUserMessage`](/Users/rajaniraiyn/work/abacusai-bot/packages/agent/src/agui/host.ts:70) reads `message.content`. `normalizeConnectionAdapter` passes a subscribe adapter’s `send` through unchanged. Forwarding the specified input directly to `run` therefore produces `rejected: empty`. **Fix:** specify and implement the conversion at the main-to-agent boundary, using `uiMessagesToWire`, preserving the client message ID. Test the real contract and host together, including attachment-only submissions.

3. **Major — F3 and §14.2 propose an echo the emitter already supplies.** [`AguiHost.onRun`](/Users/rajaniraiyn/work/abacusai-bot/packages/agent/src/agui/host.ts:327) calls `emitter.userInput` immediately after opening the run, passing the client’s message ID. Adding the proposed main echo duplicates that block. I reproduced `hellohello` by feeding two identical user blocks to the installed processor; ID deduplication does not make repeated deltas idempotent. **Fix:** remove the main injection amendment and retain exactly one agent-originated echo. Update R2-T6 to exercise that implemented path.

4. **Blocker — F2/§14.1’s full active-run hydration is incompatible with from-start replay.** `resumeInFlightRun` removes only the **last** assistant message. Earlier assistant messages from the active run remain. Replaying an earlier message ending with a tool call appends its text again after that tool. I reproduced `[text("before"), tool, text("before")]` with the installed processor. **Fix:** hydrate completed history plus the active run’s opening user message, excluding all active-run assistant messages, then rebuild the entire active run. Alternatively remove every active-run message before replay. Add a multi-round tool-loop fixture.

5. **Blocker — §3.3’s `localQueue` cannot wake an idle server read.** Once `subscribe` enters `for await` on `ai.subscribe`, local terminals are drained only between server events. A queued ack during a permission wait can arrive while that iterator is waiting indefinitely, so the synthetic terminal is stranded until another server event occurs. **Fix:** multiplex server reads, local events, gate changes and aborts through one wakeable dispatcher. Test a queued ack with an already-open subscription and no subsequent server event.

6. **Major — F6’s synthetic `RUN_ERROR` is not isolated by run ID.** `ChatClient.updateRunLifecycle` resolves its processing waiter for any terminal; `StreamProcessor.handleRunErrorEvent` sets global error state and uses the current assistant message. A terminal for rejected send B can therefore affect processing of real run A. F12’s assumed empty assistant message need not exist. **Fix:** settle rejected admissions outside the shared transcript processor, or introduce an explicitly run-scoped processing mechanism. Test B’s rejection while A has text and a running tool.

7. **Blocker — §3.3 loses replay content after a join fails partway through.** Hydration sets `yieldedSeq = N`. A join may drop the hydrated assistant, rebuild only through sequence `K < N`, then fail. Its `finally` opens the subscription at `max(N, K)`, permanently skipping the remaining reconstruction events through N. **Fix:** distinguish replay completion from iterator termination. A failure before reaching the checkpoint must restart reconstruction or rehydrate, not switch to subscription at N. Extend R2-T4 with failures after individual replay chunks.

8. **Major — `detach(); attach()` does not restart the subscription.** [`detach`](/Users/rajaniraiyn/work/abacusai-bot/node_modules/@tanstack/ai-client/src/chat-client.ts:1056) calls `cancelInFlightStream` without `abortSubscription: true`; `attach` hydrates but does not subscribe. Consequently §3.3’s resync sequence does not establish the fresh subscription lifecycle it claims. **Fix:** explicitly coordinate subscription cancellation/restart, hydration and joining, with one generation token. Test resync while a subscription is open and while a join is open.

9. **Major — empty resync hydration does not clear retained messages.** `hydrateFromServer` calls `processor.setMessages` only when `result.messages.length > 0`. If `session.cleared` was missed during disconnection and fresh hydration is empty, `detach/attach` retains the old transcript. **Fix:** recovery must explicitly replace messages with the authoritative result, including `[]`. Add an evicted-ring test where reset occurs during the gap.

10. **Major — §14.1’s snapshot cannot reconstruct the defined store.** It omits `tools.output`, `tools.display`, activity/retry state and notices. Meanwhile `store.reset` sets `appliedSeq = N`, so join replay of those CUSTOM events at or below N is ignored. A reload during bash execution loses its existing live output and can lose the pre-execution diff. **Fix:** include the required store state in the atomic snapshot, or rebuild run-scoped state from replay under a separate reconstruction cursor. Test reload during live output and permission display, before a result exists.

11. **Major — §§3.2/9.2 do not guarantee hydrated content before first paint.** `prime` returns `void`; loaders do not await it, and `useChat` starts hydration in an effect after mounting. The scroller’s 0.3.1 pending-scroll hold is mount-only and is released for an empty transcript. Thus an empty page can be captured by the navigation transition before hydration arrives. **Fix:** gate transcript mounting/navigation readiness on a resolved initial snapshot and applied opening scroll position. Test delayed and expired primes, not only warm promises.

12. **Major — §§5.1–5.4 omit required migrated-history renderers.** Transport C.3 explicitly stores notifications, collapsibles, search results, feature limits and compaction as text parts distinguished by `metadata.abacus.kind`. The proposed `TextPartView` renders all of them as ordinary Markdown. Video parts fall through to the production-null fallback. **Fix:** add metadata-aware dispatch and a video renderer, preserving migrated actions, search-result cards, collapsible titles and group information. Add actual C.3 migration fixtures to R2-T11/R2-T29.

13. **Major — ToolLine assumes the new emitter’s result shape for migrated tools.** Transport C.3 preserves legacy result content and places additional data/rejection information in result metadata; it does not promise the new `{text, formatted, display, terminal}` object. `GenericExpander`, diff and bash rendering can therefore show no detail for existing transcripts. **Fix:** define a normalization layer for both migrated and live tool results, with tests for successful, denied, cancelled, edit and terminal history.

14. **Major — F16’s queue IDs are insufficient across process replacement.** [`HostCore`](/Users/rajaniraiyn/work/abacusai-bot/packages/agent/src/agui/queue.ts) generates process-local `q-N` IDs. A stale edit of old `q-1` can resolve against new incarnation `q-1`. Main’s ID-to-index translation also retains the acknowledged drain race. **Fix:** send incarnation plus entry ID to an agent-side command that validates and mutates the current entry atomically. Return `CONFLICT` for stale identity. Test respawn and drain races through the real host.

15. **Major — §6.2 serializes access to session approvals.** Only the oldest descriptor occupies the composer, and the next appears after it resolves. No selector exposes a later descriptor, contradicting the earlier spec’s independent-answer requirement and R2-T22’s “answered in reverse order” case. **Fix:** provide selectable pending cards or an accessible pending list so either approval can be answered first. Test through rendered session controls rather than calling the runtime directly.

16. **Major — §6.4 uses incorrect permission payload fields.** The outside-directory label uses `deducedDirectory`, but the wire field is **`deducedDirectory`**. The grouped edit/write/notebook row also overlooks `write_file.content` and `notebook_edit.notebookPath`, which differ from edit’s `newContent` and `filePath`. **Fix:** define an exhaustive typed presenter per request variant. Test titles, paths and diff bodies against real descriptors, including existing-file writes and notebook edits.

17. **Major — §4.2 replaces partial `tool.display` updates.** The emitter sends `event.data` unchanged and merges it into its own accumulated display state. The legacy renderer likewise merges patches. Assigning `tools.display[key] = data` discards earlier fields when a later event supplies only counts or final content. **Fix:** merge display patches per tool key. Test successive disjoint updates before the result.

18. **Major — §7.1’s stable-prefix split changes Markdown semantics.** Blank lines outside lists, tables and fences are insufficient boundaries. Reference links and footnotes depend on definitions elsewhere in the document. I reproduced a link becoming literal `[doc][x]` when its definition was parsed in the other half. **Fix:** retain document-wide parser context or render from one parsed document; otherwise remove the split optimization. Add cross-boundary reference-link and footnote tests to R2-T18.

19. **Major — §7.5 cannot handle `file://` links through the specified `TextPart`.** The installed Markdown sanitizer removes that scheme before `ChatLink` sees it; `[file](file:///tmp/a.txt)` renders plain text. The relative-path resolution also lacks a workspace-root input in `ChatViewProps`. **Fix:** provide explicit file-link parsing/routing and workspace context, with a narrowly defined safe URL policy. Test file URLs, encoded paths and relative paths.

20. **Minor — §10’s day separators omit migrated timestamps.** Transport C.3 stores time in `metadata.tanstack.createdAt`; `normalizeMessagesDates` normalizes the top-level `createdAt` field rather than lifting metadata into it. Reading only `message.createdAt` therefore loses separators for migrated messages. **Fix:** normalize timestamps at the migration/hydration boundary or use an explicit metadata fallback. Test historical messages with and without timestamps.

21. **Major — §14.7 does not preserve outcomes for message-free runs.** It stamps the last assistant message and explicitly creates none when there is no message. A cancellation during preparation or a run producing no assistant content consequently loses its outcome on reload. Empty error messages are also hidden by §5.3. **Fix:** persist run outcomes independently of assistant content and render them from that durable record. Test reload after pre-output cancellation and failure.

22. **Minor — F10’s cited performance evidence does not establish the proposed transcript budget.** The scroller’s `PERFORMANCE.md` explicitly excludes Markdown rendering cost. Paging also accumulates loaded pages, and active-run replay can mount far more than the initial 60 messages. R2-T31 is informational even when the budget fails. **Fix:** measure fully mounted rich transcripts and long active-run replay, and define a phase gate or a concrete bounded-retention fallback before removing virtualization from the brief.
