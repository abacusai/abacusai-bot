1. **Blocker. §5.1 claims scratch initialization will exclude hugeicons because the configuration says lucide.** The scratch package has no configuration when `init --preset mira` runs. In `refs/ui/packages/shadcn/src/preset/defaults.ts`, Mira selects `iconLibrary: "hugeicons"`. The lucide configuration is written only afterward, so the dependency gate rejects the initialization it prescribes. **Fix:** configure a lucide preset before scratch initialization, then assert the generated icon library and dependencies before transplantation.

2. **Blocker. §§3.1/5.1/5.2 claim the dependency allowlist covers registry initialization and the initial component list.** The referenced base registry requires `cn`; its generated utility re-exports from `cn`. The command registry also requires `cmdk`, and `command.tsx` imports it. Neither dependency appears in §3.1. Both prescribed write gates therefore reject required output. **Fix:** add pinned `cn` and `cmdk` dependencies and verify the complete transitive registry dependency set against the allowlist.

3. **Major. §7.9 passes `system.info.platform` directly to `HotkeyOptions.platform`.** The system value uses Node platform names, including `darwin` and `win32`. The verified Hotkeys API accepts `"mac" | "windows" | "linux"`; its `resolveModifier` selects Meta only for `"mac"`. Directly passing `darwin` either fails typing or binds Ctrl on macOS. **Fix:** explicitly map system platforms to Hotkeys platforms and test shortcuts and hints using actual contract values.

4. **Major. §7.9 claims its callback guard preserves rich-text bold.** Hotkeys’ execution code calls `preventDefault()` and `stopPropagation()` before invoking the callback, with both enabled by default. Returning from `useAppHotkey` consequently still suppresses native bold. The selector also misses valid empty and `plaintext-only` contenteditable attributes. R1-T14 checks whether the toggle fires, but cannot prove native editing survives. **Fix:** disable automatic cancellation for guarded bindings, cancel only accepted events inside the wrapper, use `isContentEditable`, and test cancellation and native editing behavior.

5. **Major. §6.7 claims `default="none"` suppresses unwanted transitions despite unconditional `enter="pane"` and `exit="pane"`.** React 19.3’s `getViewTransitionClassName` gives the event-specific class precedence over `default`. Keyed enters and exits therefore remain enabled when no navigation type was added, allowing default browser animations during pending screens and masked pop-ups. R1-T11 observes added types, not actual animations. **Fix:** make enter/exit classes type-dependent with a `"none"` fallback, and add browser tests proving untyped commits do not animate.

6. **Major. §§6.1/6.7 claim the routines background stays mounted beneath its masked sheet.** Opening `/routines/new` changes the leaf route ID and therefore `leafKey`. React replaces the keyed `ViewTransition` and its entire `Outlet` subtree, including the supposedly persistent `_list` parent. Closing the sheet remounts it again, losing local state and scroll position. **Fix:** preserve the background boundary’s identity across masked navigation and render the sheet separately. Test component identity, scroll position, and local state through opening and closing.

7. **Major. §7.5 requires a 480px pane and 360px panel at a 1100px viewport with the sidebar pinned.** Rail and sidebar consume 336px, leaving only 764px before insets and the resize handle. The required panels total 840px. The acceptance assertion is geometrically impossible. **Fix:** reconcile the minimum sizes and responsive layout with the canvas contract, then test actual panel rectangles at 1100px with both sidebar states.

8. **Major. §7.5 claims the supplied class fixes drawer width at 356px.** Registry `DrawerContent` supplies `data-[swipe-axis=x]:[--drawer-content-width:75%]` and its `sm:` variant setting `24rem`. These qualified declarations override the proposed unqualified custom-property class for a right-swiping drawer. **Fix:** set the property through an inline style or an override that defeats both registry variants. Assert computed popup width at every drawer band.

9. **Major. §7.5 maps the registry drawer to the canvas without reserving the toolbar vertically.** The registry popup uses fixed positioning with `inset-y-0`; its viewport and overlay use `fixed inset-0`. An 8px drawer inset places the popup at approximately y=8, inside the 40px title-bar region, rather than below it. The scrim override changes only opacity and blur. **Fix:** explicitly constrain the side-panel popup and scrim to the canvas’s content region using `--toolbar-h`, including compact density. Verify their bounding rectangles and window-control clearance.

10. **Major. §7.4 claims a 336px leading segment aligns identity with the content pane.** `TopBar.Root` already adds `padding-left: var(--titlebar-x)`. A further rail-plus-sidebar width places identity at `titlebar-x + 336px`, while the pane starts around 336px. The simulated 70px macOS reservation exposes a 70px misalignment. **Fix:** include the reservation within the leading segment’s total width, and assert identity-to-pane alignment for all chrome modes.

11. **Major. §8.6 relies on `transport.onClose` and promises reconnection through collection retries.** The exact Transport interface inherited from spec 00 A.7 has no `onClose`. Its globally cached transport also retains the closed port; retrying table subscriptions cannot establish a replacement connection. **Fix:** specify and implement a transport lifecycle signal and recovery policy. Either reload on terminal loss or add a supported re-handshake that replaces the cached client. Test real renderer-port loss as well as memory-transport failures.

12. **Major. §12 claims `rpc-ws-smoke.mjs mutate …` mutates the running application’s main process.** Spec 00 A.8 explicitly says the WebSocket server is not wired into `main/index.ts`; its callers are a smoke test and a standalone development script. Launching that script does not attach it to the live application’s service instances and feeds. **Fix:** add an explicit development-only endpoint inside the running main process using its existing dependencies, or provide another same-process mutation harness. Test both renderer connections against those same feeds.

13. **Major. §10.2 waits for every document animation to finish or become idle.** Registry `Spinner` uses `animate-spin`, and `Skeleton` uses `animate-pulse`; these animations repeat indefinitely. The required shell gallery includes loading states, so `navigateAndSettle` cannot complete for that capture. **Fix:** wait only for finite navigation and layout animations, and freeze perpetual loading animations at a deterministic phase for screenshots. Test settling with visible spinners and skeletons.

14. **Major. §10.1 claims bounded portal containers isolate simultaneously open gallery overlays.** Changing a portal destination does not isolate Base UI’s modal focus management, document-wide hiding of outside content, or scroll locking. Multiple open modal examples can interfere with one another and hide other examples from axe. Fixed-position overlays also are not bounded merely by placing their portal inside a frame. **Fix:** isolate modal examples in separate documents or open one interactive modal at a time, with separate captures. Verify that every example remains reachable and actually participates in accessibility checks.

15. **Minor. §5.3 treats an OKLCH lightness threshold of 0.7 as sufficient foreground contrast.** Existing bot swatches `#ec4899` and `#a855f7` fall below that threshold and receive the light foreground. Their contrast against `oklch(0.985 0 0)` is approximately 3.38:1 and 3.79:1, respectively, below the normal-text requirement. **Fix:** select foregrounds using computed WCAG contrast and test every shipped swatch, rather than only the gallery’s selected sample.

16. **Minor. §7.9/R1-T14 forbid other global keyboard listeners from registry atoms.** Installed Base UI registers document Escape handling for open dismissible overlays, and `ToastViewport` registers window F6 handling when toasts exist. The proposed listener-count assertion rejects required accessibility behavior or passes only because those states were never exercised. **Fix:** assert unique ownership of application shortcuts, while explicitly allowing and testing registry Escape and F6 behavior with overlays and toasts active.

17. **Minor. §7.10’s lazy import contradicts §3.6’s export rule.** `lazy(() => import("#next/lib/devtools"))` requires the module to provide a default component export. The lint policy forbids default exports outside route files, including `lib/devtools.tsx`. **Fix:** retain a named export and adapt it: `lazy(() => import("#next/lib/devtools").then(m => ({ default: m.Devtools })))`.
