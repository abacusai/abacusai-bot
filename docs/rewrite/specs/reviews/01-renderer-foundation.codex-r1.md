1. **Blocker — §3.3: `react({ include: NEXT_SRC, compiler: … })`.** The directory-only filter replaces the plugin’s default JavaScript/TypeScript extension filter. Its compiler transform therefore receives CSS under `renderer-next` and parses it as JavaScript. An in-memory call to cached `oxc-transform-react@0.145.0` with the proposed CSS import returned `fatal: true`, “Unexpected token.” **Fix:** restrict the compiler instance to JS/TS module extensions within `renderer-next`; test CSS imports, assets, and router split-module IDs alongside both renderers’ refresh behavior.

2. **Blocker — §6.6: mask `from` values include `/_shell/(bots)/…`.** `createRouteMask` accepts route **full paths**, not route IDs. Router’s mask matching operates on URL paths; pathless layouts and route groups do not appear there. These masks fail typing or never match. R1-T1 incorrectly reinforces this by checking route IDs. **Fix:** use `/bots/$botId/details`, `/routines/new`, and `/library/connectors`; test actual masked navigation and reload behavior.

3. **Blocker — §5.1: generic `#next/*` imports make `shadcn init --preset mira --force --yes` infer the canonical aliases.** The referenced CLI infers aliases from recognizable component/lib/ui target paths. The generic wildcard provides none. Preset initialization backs up the existing configuration before inference; `--yes` does not answer the resulting configuration prompts. Restoring `components.json` afterward cannot undo writes already made using wrong aliases. **Fix:** provide explicit inferable package-import mappings before initialization, or initialize in an isolated scratch package and copy verified output. Assert every resolved destination before allowing writes.

4. **Major — §7.5: `ResizablePanelGroup direction="horizontal"` and percentage-converted numeric `minSize`.** The registry wrapper forwards the installed `react-resizable-panels` v4 API: the property is `orientation`, and numeric sizes represent pixels. A numeric percentage calculation can turn the intended 360px minimum into roughly 30–40px. **Fix:** use `orientation="horizontal"`, pixel-valued `minSize={360}` and `defaultSize={400}`, and persist the resize callback’s pixel field. Verify real dragging at the 1100px boundary.

5. **Major — §8.6: catch a thrown `TransportUnavailableError` from `router.load()`.** Router captures route-loading failures in error matches; `router.load()` need not reject. Boot then proceeds to read prefs and change language before mounting the router’s error component. The proposed static fallback does not reliably handle the failure. **Fix:** explicitly guard transport/prefs initialization outside router loading, or mount the router error state before accessing successful-load data. Test unavailable transport, rejected snapshots, and connection loss during initialization.

6. **Major — §6.1: only `_shell` sends the successful readiness barrier.** `_bare` routes include onboarding and the gallery. A direct launch into one of them never executes `_shell`’s readiness effect, leaving the host waiting for readiness. **Fix:** coordinate readiness at the root for every entry route, with explicit subscription requirements for shell and bare layouts. Test direct bare-route launch and reload.

7. **Major — §6.7: consume the transition type at the next `router.startTransition` invocation.** Router also invokes that function when offering pending matches, before the final route commit. A slow loader can consume the requested type on the pending screen. The module-global single slot also leaks or overwrites intent across cancelled, blocked, and overlapping navigations. R1-T11’s mocked setter test misses these cases. **Fix:** associate intent with a particular navigation and its successful commit; discard cancelled intent. Test the real router with delayed loaders, blocked navigation, and two rapid navigations.

8. **Major — §7.3 / §7.9: `SidebarProvider` owns exactly the intended Mod+B shortcut.** The registry handler checks `b` plus Ctrl/Meta but does not exclude Alt/Shift or editable targets. Mod+Alt+B therefore also toggles the sidebar while the application toggles the panel. Its mobile breakpoint can also activate below 768 CSS pixels through zoom, despite the native minimum window width. **Fix:** use a single application-owned shortcut handler with exact modifier and editable-target checks; choose registry atoms that do not install the conflicting handler. Test both shortcuts, text inputs, and zoom.

9. **Major — §5.2 / §7.5: the registry drawer supplies the canvas’s 45% scrim and 2px blur.** `style-mira.css` specifies `bg-black/80` for drawer and sheet overlays. The proposed untouched drawer therefore produces an 80% scrim. **Fix:** apply a scoped application override or exposed wrapper customization for the canvas opacity and blur. Verify computed styles in the real gallery.

10. **Major — §7.6: every inserted `toast-viewport` counts as occlusion until removal.** Base UI keeps the toast viewport mounted when there are no toasts. The watcher consequently publishes `any: true` for an empty viewport. The viewport’s rectangle also does not reliably describe its absolutely positioned toast children. **Fix:** observe visible toast roots, ignore empty/non-rendered rectangles, and retain actual roots during exit animations. Test an idle provider and multiple stacked toasts.

11. **Major — §7.6: a mutation-triggered rectangle snapshot tracks overlay geometry.** Resizing, scrolling, layout changes, and CSS transform animations can move an overlay without any watched attribute changing. Published rectangles become stale while the overlay remains visible. **Fix:** add resize/scroll invalidation and update geometry throughout active movement animations. Test a positioned popover during resize and an entering/exiting drawer.

12. **Major — §13: diverging old/new prefs are “accepted.”** This conflicts with spec 00’s migration/provenance requirements and the rewrite’s preservation requirement. Switching generations can change theme or sidebar state, and later migration can apply stale preferences. **Fix:** implement the specified provenance-aware synchronization and make it a foundation prerequisite; test legacy writes, next-renderer writes, and repeated generation switching.

13. **Major — §9.2: use `navigator.languages` when `prefs.language` is “still the default.”** The public prefs value cannot distinguish an explicitly selected `en-US` from an unset default `en-US`; migration provenance is private. A user choosing English can therefore receive another language on restart. **Fix:** expose an explicit system-language preference or public initialization indicator. Test unset language separately from explicit English.

14. **Major — §7.7 / acceptance: no wrong-theme flash at launch.** Applying the system theme before asynchronous transport and prefs loading still permits the HTML/background and native window to paint in that theme. Waiting before React rendering does not prevent this, particularly when the stored preference opposes the OS theme. **Fix:** provide startup theme information before showing the window, coordinate native theme and renderer readiness, and test delayed initialization with opposite stored/system themes.

15. **Major — §10.2: `dataset.ready === "1"` plus two frames makes each screenshot ready.** The flag is set once by `_shell` and remains true across navigation. Subsequent captures can show the previous route, pending content, or an unfinished 200ms transition. Bare routes do not set it themselves. **Fix:** await a route-specific successful commit and completion of animations, fonts, and layout before capturing.

16. **Major — §10.2: `ABACUSBOT_DEV_WINDOW_BOUNDS=Wx800` exercises the requested width bands.** Native window bounds are outer dimensions; shell breakpoints use CSS viewport width. Native frames and zoom can move nominal 1000/900/800 captures into another band. **Fix:** size the content viewport and assert `window.innerWidth` before capture. Exercise both sides of each boundary under native-frame fallback and WCO.

17. **Major — §5.4: an exact shadcn CLI pin makes registry regeneration reproducible.** Registry content is fetched separately and can change without a CLI release. CI can fail on an unchanged commit or silently establish a new upstream baseline. Regenerated output also needs the same formatting pipeline as committed files. **Fix:** pin or snapshot registry content and dependencies, record hashes, and compare equally formatted output.

18. **Major — §6.1: `routines.new.tsx` being a child keeps the index visible beneath its sheet.** The index and `new` routes are siblings. Router’s `<Outlet>` renders the matched child; the index is no longer matched when `new` is active. **Fix:** render the persistent routines list in the parent layout and sheets through its outlet, or specify explicit background-location rendering. Test the visible background, including masked reloads.

19. **Major — §12: a second legacy profile sharing the same home proves live collection updates.** Table feeds are driven by mutations in their own main process. Another process writing the same JSON files does not produce those change batches; cached stores and concurrent writes add further risk. **Fix:** run both renderer connections against one main process, or explicitly implement cross-process watching and write coordination before supporting this scenario.

20. **Minor — §6.7: path-prefix inference supplies all drill-in/back transitions.** `/bots/new` → `/bots/<id>` and equivalent session navigation are sibling paths, so the described algorithm supplies no forward transition. Prefix inference also lacks history direction for sibling navigation. **Fix:** define semantic route relationships and history direction, with explicit intent for creation-to-detail navigation; add those cases to R1-T11.

21. **Minor — §10.1: adding `.dark` only to the second container produces simultaneous light/dark previews.** If `<html>` is already dark, the first container inherits dark tokens too. Portaled components also escape the preview container. **Fix:** explicitly scope both theme token sets and portal destinations, or use isolated documents. Test the gallery while the application itself is dark.

22. **Minor — §3.7: share `NEXT_SRC` through `vite/next-src.ts`.** `tsconfig.vite.json` is composite and includes only `vite.config.ts` and `vitest.config.ts`. Importing the new helper without expanding its file set produces the composite-project file-list error. **Fix:** include the helper directory or place the constant in an already included module; run the referenced TypeScript build.

23. **Minor — R1-T9: `OVERLAY_SLOTS` equals all installed overlay-like registry slots.** The list deliberately includes menubar/navigation-menu slots from components not installed in phase 1, while drawer/toast wrappers introduce additional matching slots. The proposed equality mixes installed slots, reserved future slots, and non-occluding containers. **Fix:** distinguish installed occluders, reserved slots, and explicitly excluded containers; assert coverage and selector correctness separately.

24. **Minor — §12: the old renderer’s entire diff must remain empty.** §9 requires adding shared translations under `src/renderer/locales`, making that acceptance condition impossible. **Fix:** permit the specified locale-data additions while requiring an empty legacy implementation diff and preservation of existing translation keys and values.
