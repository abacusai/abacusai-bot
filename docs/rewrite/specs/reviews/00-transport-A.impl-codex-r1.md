1. **major — [procedures/impl.ts:75](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/rpc/procedures/impl.ts:75).** The queue limits do not bound a slow renderer’s backlog. oRPC 1.15.4 eagerly drains server iterators into its client’s unbounded `AsyncIdQueue`; `postMessage()` provides no consumption backpressure. A reproduction produced 20,000 events with zero client `next()` calls. Add consumption acknowledgements or credits so pending limits cover unconsumed transport data. Test through the real adapters with a stalled consumer.

2. **major — [create-transport.ts:41](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer-next/data/transport/create-transport.ts:41).** `Transport.close()` closes the DOM port without closing oRPC’s local peer. The adapter relies on a `close` event, which [the HTML specification](https://html.spec.whatwg.org/multipage/web-messaging.html#disentangle) fires only at the other endpoint. Pending calls and iterator reads remain unresolved and retain their queues. Wrap the port to notify local close listeners exactly once, as main’s `trackPort` does. Verify pending-call cleanup in real Electron; Node channels mask this difference.

Reopening after reload or overflow therefore loses already-pending connector and permission requests, potentially leaving tools blocked indefinitely. Enumerate all pending requests for global subscriptions, or require a conversation key. Test reopening with requests already pending.

4. **major — [devices.ts:33](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/rpc/procedures/devices.ts:33).** Device chunks do not follow the required dual-delivery path. RPC starts send chunks only to the bus; legacy starts pass the raw sender and send only through legacy IPC. The mounted transports see different events. Use one shared sender or producer that performs both deliveries, and call it from both start handlers.

5. **major — [devices.ts:99](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/rpc/procedures/devices.ts:99).** The chunk subscription has no replay or keyframe barrier. Clients must obtain `streamId` from `start` before subscribing, but scrcpy already drains video before startup returns, including before awaiting its control connection. The initial keyframe can be discarded while no listener exists, leaving subsequent H.264 frames undecodable. Buffer from startup through subscription, or negotiate the subscription before starting capture. Reopening must begin with codec configuration and a keyframe.

6. **major — [terminal.ts:63](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/rpc/procedures/terminal.ts:63).** `terminal.output` ends only on `terminal-exited`. Explicit close, scope disposal and workspace disposal invalidate/remove the runtime before killing the PTY, so its exit callback is suppressed by `isCurrent`. Scope promotion also changes the key/generation that this listener filters. These subscriptions remain parked with bus listeners attached for the document’s lifetime. Publish an RPC lifecycle termination for closed or superseded generations, record the terminal’s final state, and test close/disposal/promotion cleanup.

7. **major — [index.ts:679](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/index.ts:679).** Window state updates target only the active renderer; `publishChromeState` does likewise. A hidden swap candidate captures an initial snapshot but misses subsequent fullscreen, maximize and chrome changes because its subscription filters by its own contents ID. Promotion publishes no fresh snapshot, so it can become visible with stale state. Fan out these facts to the window’s registered views, or refresh them atomically on promotion. Test a change between candidate subscription and flip.
