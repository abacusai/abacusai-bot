1. **Blocker. §§3.1.1 and 5.2 claim a queued acknowledgement can settle the client-side send without a terminal.** In reference `ai-client/src/chat-client.ts`, `streamResponse()` awaits `connection.send()` and then a separate `processingComplete` promise. Returning from a `SubscribeConnectionAdapter.send()` does not resolve that promise. A send from a second window while the host is busy can therefore remain loading until an unrelated run terminates. **Fix:** define an application-level admission path for queued input outside ChatClient’s send lifecycle, or extend the client integration with explicit acknowledgement settlement. Test settlement before the existing run ends.

2. **Major. §3.1.1 assumes busy composer input reaches the host’s existing steering/permission queue.** ChatClient’s `sendMessage()` intercepts busy input and queues it locally by default. PLAN.md explicitly selects `whenBusy:"queue"`. Those messages reach the agent only after successful completion; they cannot steer the current turn, and client Stop/error clears them. Today the host receives them immediately and preserves queued messages across Stop. **Fix:** make the host queue authoritative and route busy composer submissions directly to its admission procedure. Wire edit/remove/clear to that queue. Test input during streaming, permission waiting, Stop and error.

3. **Major. §§3.5.4–3.5.5 say unattached permissions render in the kit’s Interrupts slot while `ChatClient.interrupts` remains empty.** `ai-react/src/chat-ui/create-ui.tsx:818` obtains that slot’s items solely from `chat.interrupts` through `selectChatUI`. `onCustomEvent` does deliver the descriptor payload, but updating a separate store does not populate this dispatcher. Unattached sandbox/network requests can consequently have no visible answering control. **Fix:** specify an application-owned permission list in the layout and notch, subscribed directly to the descriptor store. Test an unattached request with the real `createChatUI` layout.

4. **Major. §3.6 claims `SubagentHandle.stop()` sends `cancel`.** Reference ChatClient’s `stopSubagent()` marks the child errored locally and calls `this.abortController?.abort()`. A client merely subscribed to a server-initiated or synthetically hydrated run has no request abort controller, so the agent continues working. **Fix:** give the card an application-owned Stop action that explicitly calls the cancel procedure for the owning parent run. Test Stop from a second window and from a restored card.

5. **Major. §5.3 calls its recovery authoritative, but snapshots contain only completed runs and live bookkeeping.** Already-emitted text, reasoning, resolved tools, finished children and the current user input are absent from `SessionSync`. Reload after a tool finishes but before the run ends loses that tool and its output; reload halfway through a paragraph retains only subsequent deltas. A ring gap permanently loses the same content. **Fix:** hydrate the complete current-run transcript from main’s processor state, alongside completed history, at a defined cursor. Test recovery after completed tools/children and after substantial text has already streamed.

6. **Major. §5.3 sends the persisted snapshot before asking for `sync`, without defining an atomic recovery boundary.** A run can finish between those steps. The snapshot excludes it, `sync.run` is then null, and switching to events after the sync point skips its terminal and content. Descriptor changes can also race the final store replacement. **Fix:** buffer delivery during recovery and obtain transcript, live state and a monotonic cursor as one consistent checkpoint. Replay buffered events strictly after that cursor. Test a terminal and permission resolution occurring between snapshot selection and sync receipt.

7. **Major. §5.3 re-announces every unresolved tool with `START/ARGS/END`, including calls whose arguments are still streaming.** `SessionSync.openToolCalls` has no argument-phase flag or accumulated raw argument string. Reference StreamProcessor accepts subsequent ARGS after END, but another END is ignored when the call is already `input-complete`. Hydration can therefore replace partial input with `{}` and prevent the real final canonical input from applying. **Fix:** snapshot each call’s phase, accumulated argument bytes and canonical input separately. Emit END only for calls whose input actually ended. Test recovery midway through argument generation.

8. **Major. §5.3 leaves the persisted-transcript-to-`MESSAGES_SNAPSHOT` conversion unspecified.** StreamProcessor produces `UIMessage[]`, whereas `MESSAGES_SNAPSHOT.messages` uses AG-UI messages. Its handler reads canonical `content` and `toolCalls`, not arbitrary UI `parts`; child cards and reasoning also require the reference wire encoding. Passing processor output directly produces incomplete history. **Fix:** name and pin the conversion contract, including subagent grouping, reasoning, tool metadata and errors. Round-trip actual processor output through a fresh processor rather than supplying an already-converted fixture.

9. **Blocker. §3.5.3 exempts legacy permission responses from lineage validation because “only main writes it” and cites the child ownership guard.** That guard protects incoming child callbacks, not responses originating from an old renderer card. `AgentCommunicationService.respondPermission()` dispatches an ID to the current runtime. During the explicitly supported old-renderer coexistence, a delayed `perm-1` response can approve the replacement process’s unrelated `perm-1`. **Fix:** bind renderer permission actions to the originating incarnation in main and reject stale actions before dispatch. Keep automatic responses tied to the exact runtime that produced the request. Test an old-window answer after respawn.

10. **Major. §§3.1.1 and 6.3 reserve admission only for `run`, while legacy turn starters retain their current handlers.** During awaited `forwardedProps.model`, `reserved` is true but the extracted legacy `runTurn()` checks only `busy`. A messaging/routine `send` or idle `enqueue` can start another turn against the already-open run. **Fix:** apply one synchronous admission guard to every turn-starting command, including drains and dequeue. Add mixed `run`/legacy-command concurrency tests.

11. **Blocker. §§3.1.1 and 3.8 do not invalidate a reserved prompt when Stop/reset lands during model application.** Stop can close the run while `setModel()` is awaited. The original handler then resumes and calls `runTurn(text, token)` anyway, executing a prompt the user stopped, potentially against the reset conversation. Token-checked settlement does not prevent execution. **Fix:** capture the admission generation and check cancellation/ownership after every awaited preparation step, before prompting. Test delayed model application followed by Stop and reset.

12. **Major. §2.2 accepts `cancel.runId`, but §§2.2 and 3.8 run the unconditional legacy Stop handler.** A delayed abort from run A can stop run B after A has already settled and the queue has drained. Request-scoped adapter aborts make this a normal race. **Fix:** validate a supplied run ID against the current admitted turn before invoking Stop; keep the explicit legacy `stop` command unconditional. Test late cancellation after replacement admission.

13. **Major. §4 permits hidden-turn permissions after the user’s run has settled, but §3.5.3 requires an owning run in every permission lineage.** There is no open run from which to construct that lineage, and `SessionSync.run` is null. The protocol never defines which run ID such a descriptor carries or how its answer passes validation. **Fix:** introduce an internal turn identity that survives into housekeeping, or define a separate session-scoped permission lineage. Test a hidden-turn permission through fresh attachment, response and expiry.

14. **Major. §2.4 promises transparent exit-78 fallback to NDJSON, but does not preserve the new renderer’s protocol.** Today [cli-manager-service.ts](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/session/cli-manager-service.ts:685) treats an early close as failure, emits session closure and deletes the runtime. A respawn in NDJSON mode also has no AG-UI stdout for `ai.subscribe`, nor acknowledgements for `run`. **Fix:** specify startup fallback before publishing failure/closure, negotiate the effective wire mode, and provide a working renderer adapter for NDJSON fallback. Test the actual manager and new ChatClient end to end.

15. **Major. §2.4 detects an unusable fd through the first write while guaranteeing exit 78 before any stdout.** Stream write errors are asynchronous. `compat.write()` can return before its error arrives, after which `agui.accept()` writes stdout. Later fd-3 errors are merely logged, leaving main’s taps without events while AG-UI continues. **Fix:** complete channel preflight before session startup or either protocol writer is enabled; define channel-loss handling that prevents silent tap loss. Test asynchronous first-write failure and compat disconnection after ready.

16. **Major. §§3.1.5 and 6.2 put `finishReason:"tool_calls"` on a final run terminal when pi’s last stop reason is `toolUse`.** Reference ChatClient’s `isIntermediateToolTurn()` treats that terminal as a handoff and deliberately skips processing completion; StreamProcessor also skips finalization. This contradicts the promised terminal guarantee whenever a user-visible turn ends on a tool-call message. **Fix:** use final-turn finish metadata that the client treats as terminal. Reserve `tool_calls` for an actual continuation protocol. Test a settled run whose last assistant stop reason is `toolUse`.

17. **Major. §3.3.8 maps cache accounting incorrectly.** Installed `@ag-ui/core@1.0.0` defines `inputTokens` as including cache-read and cache-write tokens. The proposed mapping uses only `input`, but adds caches to `totalTokens`, so `totalTokens !== inputTokens + outputTokens`. `TurnUsage.model` can also be null, while canonical usage accepts an optional string. **Fix:** set `inputTokens = input + cacheRead + cacheWrite`, retain the cache breakdown fields, and omit an unknown model. Add cached-usage and null-model conformance cases.

Verify the built subpath imports successfully in the renderer bundle and packaged app.
