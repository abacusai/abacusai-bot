1. **Major — apps/desktop/src/main/services/session/thread-store.ts:54–56.** Every read error becomes `"missing"`. An unreadable AG-UI file in a writable directory can therefore be atomically replaced by dual-write or repair, destroying its messages and run outcomes. **Fix:** distinguish `ENOENT` from other I/O failures and refuse replacement when the existing twin cannot be read.

2. **Major — apps/desktop/src/shared/transcript/thread-file.ts:170.** Freshness depends entirely on timestamps. Two v1 saves can share the same millisecond; if the second dual-write fails, hydration permanently accepts the older twin as current. The failure test sleeps 5 ms, masking this case. **Fix:** persist a source fingerprint or monotonic revision and compare it when timestamps match; test with a fixed clock.

3. **Major — apps/desktop/src/main/services/session/thread-store.ts:125.** Cleared-history protection excludes AG-UI twins. If reset removes v1 but v2 deletion fails, hydration immediately returns the surviving AG-UI history. **Fix:** persist a reset/deletion tombstone checked before returning either source kind. Test failed v2 deletion, including across restart.

4. **Major — apps/desktop/src/main/migrations/steps/004-archive-transcripts-v1.ts:125, through main/migrations/runner.ts:332–343.** A partial commit has no durable completion marker. If deleting its journal fails, normal launch continues; the app can append AG-UI history to a newly created twin. Next launch treats the journal as interrupted and deletes that twin during rollback. **Fix:** durably record committed partial transactions separately from applied steps; recovery should finish cleanup while leaving the step eligible to rerun.

5. **Major — apps/desktop/src/shared/transcript/v1-to-ui-messages.ts:190–199.** Legacy protocol display fields remain only under `call.metadata.abacus.legacy`. The §5.4a migrated consumer reads `result.metadata.abacus.data`, so legacy reads lose their structured content/line counts and edits lose their before/after diffs. **Fix:** normalize `toolDisplayData`, `displayContent`, and `old_content` into the appropriate `ToolResultData`, preserving the original legacy content. Add successful legacy read/edit goldens.

6. **Major — apps/desktop/src/shared/transcript/v1-to-ui-messages.ts:285–318.** Collision handling covers message IDs only. Repeated tool-call IDs within one assistant message produce ambiguous call/result pairing; repeated segment IDs also produce identical result IDs. A reproduced pair yielded two calls named `c` and two results named `t:result`. **Fix:** assign occurrence-specific pairing IDs while retaining original IDs in provenance, or separate conflicting occurrences into distinct messages. Assert pairing uniqueness in C-T2.

7. **Minor — apps/desktop/src/shared/transcript/v1-to-ui-messages.ts:654.** Sub-agent children bypass `takeTurnFields`. Persisted child text loses `messageIndex`, `regenerateAttempt`, and `versions`, which legacy hydration preserves. **Fix:** collect turn fields on child targets and preserve child message boundaries when ordinals change; add a versioned child fixture.

8. **Minor — apps/desktop/src/shared/transcript/v1-to-ui-messages.ts:155–162.** Any object-valued `toolCall` is accepted, even with invalid required fields. For example, `name: 7, args: [1,2]` becomes an empty name and `{}`, irreversibly discarding the input rather than producing the documented lossless unknown output. **Fix:** validate required call fields before normalization and retain invalid shapes as `unknown/raw`.

9. **Minor — apps/desktop/src/shared/transcript/v1-to-ui-messages.ts:244–249.** A historical successful call without a stored result produces no result part. Legacy hydration synthesizes a successful result, but the §5.4 consumer labels this migrated call `"stopped"`. The existing `s-noresult` golden embeds that regression. **Fix:** synthesize an empty complete result for historical successful calls and assert the rendered status.

10. **Minor — apps/desktop/src/shared/transcript/v1-to-ui-messages.ts:343–346.** ID allocation becomes quadratic for repeated IDs because every claim searches again from suffix `1`. Reproduction took approximately 59/229/911 ms for 1k/2k/4k duplicate user IDs; a large damaged file can monopolize startup without yielding. **Fix:** maintain the next suffix per base ID and add a large duplicate-ID case.
