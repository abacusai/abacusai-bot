1. **Blocker — Worktree Files and Changes use the wrong checkout.** §§13.1–14.5 promise worktree-rooted trees, search, mutations and diffs. [Main’s implementations](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/service-host.ts:1789) still use the active workspace root; sibling worktrees produce empty trees, and relative mutations can affect the primary checkout. `gitState` has no checkout identity. **Fix:** require checkout-aware tree/search/rename/trash/diff/git-state APIs now. §26.4(d)’s deferred per-workspace amendment is insufficient. Test a sibling worktree and prove the primary checkout remains untouched.

2. **Blocker — The first-message handoff does not preserve admission IDs.** §8.6 and §26.2 claim a pre-minted run ID prevents duplicate sends across reloads, but `pendingSubmit` only specifies `forwardedProps`. [Chat-kit `session.submit`](/Users/rajaniraiyn/work/abacusai-bot/docs/rewrite/specs/02-chat-kit.md:318) generates fresh run and message IDs. Reloading after acceptance but before cleanup can start another run. **Fix:** persist the complete submission envelope and expose admission with caller-supplied IDs. Test reload after acceptance, before clearing `pendingSubmit`.

3. **Major — Cold session links can falsely report deletion.** §5.3 reads `sessions.get()` immediately, assuming `_shell` finished preloading. [Spec 03’s amendment](/Users/rajaniraiyn/work/abacusai-bot/docs/rewrite/specs/03-bots.md:1094) explicitly rejects this assumption because matched loaders run concurrently. **Fix:** await sessions/workspaces readiness in every loader that reads them, including index and new-session resolution. Extend R4-T3/T4 with delayed snapshots on cold direct navigation.

4. **Major — Worktree retries recreate an already-created session.** §8.6 persists the session before materialization; §6.4 deliberately retains that session after failure. Retry repeats insertion, causing a duplicate-key failure or the proposed `CONFLICT` handler to mint another session. **Fix:** persist the creation stage and session ID in the start draft, then resume the existing operation. Test failed materialization followed by Retry and “No worktree,” asserting one session and one first message.

5. **Major — Startup does not receive the selected draft model.** §§8.6, 9.2 and 26.3 start from the session’s pinned model, but [session insertion](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer-next/data/db/tables.ts:105) sends only ID/workspace, and newly created records have null model/mode. Startup therefore uses defaults and relies on a later forwarded model change. This defeats the stated avoidance of the startup model race. **Fix:** persist the selected model before either startup path, and give concurrent startup callers one authoritative configuration. Test a selected model differing from an unavailable app default.

6. **Major — Start-page mentions search a different workspace from the selected one.** §8.3 changes draft workspace and prefs without switching main, while §8.1 promises search over that workspace. [ `files.search` ](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/service-host.ts:1805) always searches the active workspace. **Fix:** contextualize search, or explicitly activate the chosen workspace on real navigation/pick. Test choosing B while A remains active.

7. **Major — Execution-target selection has neither a valid sandbox mapping nor a send step.** §8.2 offers “Sandboxed” through `settings.execBackend`, stores every choice as draft state, and §8.6 never applies `execTarget`. [Backend IDs](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/shared/contract/settings.ts:26) contain `local`, `docker` and remote backends, not a sandbox backend; sandboxing is separately controlled by agent mode. **Fix:** define the backend/mode mapping and when the global backend mutation occurs. Test actual execution after each choice, including refusal and fallback.

8. **Major — Connector-request parity is incorrectly deferred.** S65 says the molecule belongs to phase 5 and cites 03 P63. [Spec 03 r2](/Users/rajaniraiyn/work/abacusai-bot/docs/rewrite/specs/03-bots.md:765) already implements the shared actionable card and explicitly reserves session reuse. A placeholder cannot release a session tool waiting for connection. **Fix:** reuse the card here, including pending-request snapshots, field flows, decline and response handling. Add a session test that completes the connection and resumes the suspended turn.

9. **Major — Agent-requested file previews have no session consumer.** §6.1 maps `files.events` only to tree invalidation; S77 inventories preview types but omits `preview-open` delivery. The shipped [shell-level preview bridge](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer/utils/preview-utils.ts:125) opens supported deliverables in their originating conversation and preserves background tabs/unread state. **Fix:** add a shell-mounted session preview consumer and a parity row. Test URLs, files, unsupported types and background conversations.

10. **Major — Hidden running terminals disappear on reload.** §10.2 reconciles only terminal states with `visible !== false`, while §11.1 hides every inactive tab. [Main’s hide operation](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/conversation/conversation-terminal-runtime-registry.ts:380) sets that flag without closing the PTY. **Fix:** reconcile resource existence independently of presentation visibility. Remove tabs only after disappearance or retirement. Test multiple hidden terminals across reload.

11. **Major — The 5 MB reload gate exceeds retained scrollback.** R4-T29 and §25 require byte-identical recovery after a 5 MB burst. [Main retains only 2 MB](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/conversation/conversation-terminal-runtime-registry.ts:143); Ghostty also limits scrollback to 10,000 lines. Offsets cannot recover evicted bytes. **Fix:** distinguish lossless live delivery from bounded replay and assert the exact retained tail plus replacement-snapshot behavior. If complete recovery is required, amend storage/retention explicitly.

12. **Major — Focused-terminal tab shortcuts do not reach the dock.** §11.4 claims `Ctrl+Tab`/`Mod+W` are not consumed. [Ghostty’s modified-key encoder](/Users/rajaniraiyn/work/abacusai-bot/node_modules/ghostty-web/dist/ghostty-web.js:954) stops propagation, while TanStack Hotkeys listens during bubbling. **Fix:** dispatch dock chords explicitly from the terminal adapter before terminal encoding. Add real focused-terminal keyboard tests, preserving ordinary shell control sequences.

13. **Major — “Move terminal input unchanged into shared” retains a renderer dependency.** §11.4 and §26.9 require an unchanged move, but [terminal-keys.ts](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer/terminals/terminal-keys.ts:10) imports renderer `window-chrome`, whose platform lookup uses legacy `window.api`. **Fix:** inject platform information into the shared adapter and supply it from each renderer. Use thin legacy wrappers and test both platform paths.

14. **Major — Embedded PDF/HTML support is definitively unavailable through the proposed browser API.** F8, §13.3 and §27.2 call `file:` navigation unverified. [Main’s URL guard](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/browser/electron-browser-runtime.ts:63) explicitly rejects it in materialize/present/navigation. R4-T30’s “opens or fallback shows” permits loss of embedded previews while still passing. **Fix:** specify guarded local-file presentation and its main amendment, or explicitly retire embedded previews and change the parity acceptance.

15. **Major — Multiple browser leaves compete for one native presentation.** §§10.4–10.5 make each leaf’s active tab visible, including multiple Browser tabs. [Main `present`](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/browser/electron-browser-runtime.ts:268) hides the previously presented runtime. **Fix:** define one presentation owner with captured placeholders and explicit activation elsewhere, or amend main for multiple presentations. Test two browser leaves through focus, resize and occlusion.

16. **Major — S110 claims an iOS fallback that §16 omits.** The old [device panel](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer/components/device/device-panel.tsx:320) falls back from native streaming to Simulator-window capture before screenshot polling. §16.2 jumps directly to polling, and R4-T32 omits window capture. **Fix:** port the fallback, permissions, cropping and media-track cleanup, or mark its removal as an explicit behavior change.

17. **Major — Pixel persistence uses a percentage callback without conversion.** §10.3 sends `onLayoutChanged` values into pixel preferences, and §10.4 stores split sizes similarly. [Group `Layout`](/Users/rajaniraiyn/work/abacusai-bot/node_modules/react-resizable-panels/dist/react-resizable-panels.d.ts:623) contains percentages; numeric Panel constraints being pixels does not change that. The installed root package is also 4.14.1, not the cited 4.12.3. **Fix:** persist `Panel.onResize().inPixels` or explicitly convert percentages, define each split’s preference keys, and test restoration after window resizing.

18. **Major — Tool-diff contents cannot reach the full-diff dialog through the declared API.** §14.5 says the kit passes `originalContent`/`newContent`; §26.2’s callback passes only path, source and tool key. No public resolver supports that key, especially after masked-route reload. **Fix:** define a typed diff resolver using stable thread/tool identity and hydrated content, with an explicit unavailable-history state. Test opening and reloading a tool-sourced diff.

19. **Major — Cancellation produces successful-completion cues.** §19 derives uncached-thread success from transition to `idle`. [Turn state](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/shared/contracts.ts:468) contains no outcome or run ID, and [Stop sets `idle`](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/session/session-turn-state-service.ts:99). Consequently background cancellation can produce “Task completed.” **Fix:** add a lossless terminal-outcome notice analogous to spec 03’s bot completion amendment. Test success, cancellation, failure and duplicate delivery.

20. **Major — The Chat pseudo-tab contradicts the panel-open rule.** §10.4 says absent `tab` selects Chat in full view. §§10.1–10.3 say absent `tab` means no strip and no open dock. Selecting Chat therefore cannot preserve the full-view tab strip as promised. **Fix:** define separate, unambiguous Chat-selection and panel-closed states, then amend schemas/layout rules together. Test Chat selection, close-strip, reload and back/forward.

21. **Major — Same-stat file edits leave stale diffs and review marks.** §6.1 invalidates diffs only through git-state batches; §14.4 clears Keep when additions/deletions change. [Git-state equality](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/rpc/tables/git-state.ts:32) ignores timestamps. Changing one replacement into another can retain identical status/statistics, producing neither invalidation nor mark clearing. **Fix:** use content/version-based invalidation and review fingerprints. Test edits with identical addition/deletion counts.

22. **Minor — Ghostty’s repaint fallback is a no-op.** §11.3 proposes optional `refresh`, then same-size `resize`. Ghostty 0.4.0 has no public `refresh`, and [same-size resize returns immediately](/Users/rajaniraiyn/work/abacusai-bot/node_modules/ghostty-web/dist/ghostty-web.js:2439). **Fix:** specify an effective repaint adapter for this version. Verify real canvas pixels after hidden output and reappearance; a typing test cannot establish painting.

Exercise the real helper’s echo and rollback paths.
