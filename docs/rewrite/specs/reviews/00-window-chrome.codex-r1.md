1. **Major.** §4 claims `setTitleBarOverlay({ height, color, symbolColor })` works on macOS. Installed Electron is **43.4.1**, and [electron.d.ts](/Users/rajaniraiyn/work/abacusai-bot/node_modules/electron/electron.d.ts:3539) marks this method Windows/Linux only. Constructor support for `titleBarOverlay.height` does not imply a macOS runtime setter. Electron’s [API documentation](https://www.electronjs.org/docs/latest/api/base-window#winsettitlebaroverlayoptions-windows-linux) retains that restriction. Fix: define a separate macOS density implementation, or require window recreation there. Test the actual platform method availability.

2. **Major.** §6 treats macOS fullscreen as a rectangle whose `x` merely becomes zero, and the hook falls back only when the API is undefined. Electron 44 instead [disables WCO and returns an empty rectangle](https://raw.githubusercontent.com/electron/electron/44-x-y/shell/browser/native_window_mac.mm). Chromium [removes the CSS environment variables](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/frame/local_frame.cc), so CSS uses a 40px bar while JS reports height zero. The Toaster moves to 10px and overlaps the toolbar; compact density also becomes 40px in fullscreen. Fix: distinguish native overlay geometry from application toolbar geometry and define consistent hidden-overlay behavior. Test entry, exit, and compact density with an existing API returning `visible=false`.

3. **Major.** §9 says to fix Electron 44 clipboard migration by awaiting `clipboard.readImage()`. That method is **removed**, not converted to a Promise. The installed 43.4.1 declaration returns `NativeImage`, but [44’s breaking changes](https://www.electronjs.org/docs/latest/breaking-changes#api-changed-clipboard-module-rearchitected-to-align-with-the-w3c-clipboard-api) require `clipboard.read()`, selecting an image MIME type, and awaiting `item.getType()`. The current handler catches failures and returns null, so a runtime failure silently disables “Paste image.” Fix: rewrite the handler to read image blobs, preserve the attachment contract, and test image, empty, and non-image clipboards.

4. **Major.** §6 assumes unsupported Linux WCO automatically leaves server-side decorations and usable controls. Setting `titleBarStyle: "hidden"` actively requests removal of the normal title bar; Electron [documents that Windows/Linux controls then depend on WCO](https://github.com/electron/electron/blob/main/docs/api/structures/base-window-options.md). Missing overlay geometry does not establish that a compositor restored native controls. Fix: specify and implement a verified native-frame fallback for unsupported configurations. Require working close, maximize, minimize where available, and window movement on both Wayland and SSD configurations before enabling the hidden-titlebar path.

5. **Major.** §11 says steps 1–2 can ship before renderer migration. Step 2 enables Linux caption buttons while the current renderer still reserves only **16px on the right**, because `TITLEBAR_END_INSET` branches exclusively on Windows. It also changes Windows native height to 40px while the existing renderer remains 32px. Fix: ship native options and all renderer geometry consumers together, or retain existing options and heights until migration lands.

6. **Major.** §8 claims native browser bounds “need nothing,” including alongside §6’s high-zoom support. [roundedBounds()](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer/components/browser/browser-runtime-surface.tsx:87) sends CSS pixels directly to `view.setBounds`, which uses device-independent pixels. WCO variables being zoom-adjusted does not convert the browser bounds. At renderer zoom other than 1, the native view is misplaced and incorrectly sized. Fix: convert bounds using the presenting renderer’s zoom factor before rounding and clamping, or explicitly enforce renderer zoom 1. Test multiple page zooms separately from display scaling.

7. **Major.** §8 assumes DOM-derived bounds stay synchronized with the rewritten shell. The browser surface observes **size**, window resize, and scroll, but not position-only movement. PLAN’s animated sidebar/panel transitions can translate a host without changing its dimensions; a `ResizeObserver` will not track that motion. Fix: hide the native view during those transitions and restore it after measuring, or update bounds throughout the animation. Test translation-only movement and verify native input remains aligned.

8. **Major.** §6 limits `no-drag` handling to interactive children of the title bar. Portaled menus, dialogs, sheets, and tooltips can overlap a native drag region without being its descendants. DOM stacking does not itself subtract that region, and the existing UI components contain no `app-region` exclusions. Fix: define `no-drag` treatment for overlapping popup surfaces and appropriate backdrops. Test clicking and dismissing a popup positioned over the title bar, including `_bare` routes.

9. **Major.** §10 directs the CSS test to an “existing vitest browser project.” [vitest.config.ts](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/vitest.config.ts:62) has no such project. Renderer tests run in jsdom; `ghostty-scrollback.browser.test.ts` is a Node test that spawns Electron. The proposed `.tsx` test therefore cannot validate computed `env()` layout as specified. Fix: add a configured browser project or use the existing Electron harness through a registered Node integration test.

10. **Major.** §§10–12 do not test the central dependency through the actual `BaseWindow`/`RendererHost` lifecycle. Overriding `--titlebar-x` proves CSS consumption but cannot catch failed WCO forwarding, incorrect clipping, or geometry initialization after a renderer swap. Fix: add an Electron integration test covering initial load, resize, fullscreen, and `RendererHost.swap()`, comparing API geometry with computed CSS and checking titlebar/button clearance.

11. **Minor.** §7’s fullscreen deletion list omits `isFullScreen()` in [preload/index.ts](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/preload/index.ts:74), its declaration in `preload/index.d.ts:40`, and `window:is-full-screen` in `main/index.ts:1099`. 12. **Major.** §13 proposes `@supports not (top: env(titlebar-area-x))` as a fallback for missing WCO forwarding. That tests CSS syntax support, which Chromium has even when Electron supplies no geometry. The fallback never activates in the failure it is intended to mitigate. Fix: make verified forwarding a release gate, or use an explicit capability state with a tested fallback. Test “CSS supports `env()`, native controls exist, geometry is unavailable.”
