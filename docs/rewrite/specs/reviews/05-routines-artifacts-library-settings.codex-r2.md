1. **Major — Terminal handler return value is reversed.** [§21.3](/Users/rajaniraiyn/work/abacusai-bot/docs/rewrite/specs/05-routines-artifacts-library-settings.md:1111) says to return `false` after dispatching a chord “so no bytes reach the PTY.” Installed ghostty consumes the event when the handler returns **true**; false continues encoding. This also contradicts 04 r3 §11.4. **Fix:** return true for consumed actions and false for unhandled keys. Extend R4-T39 to verify exactly one action, no corresponding PTY bytes, and unchanged ordinary input.

2. **Major — The new terminal shortcut is missing from terminal dispatch.** §21.3 registers `new-terminal-tab` as `Mod+backtick`, but excludes it from the adapter’s forwarded action list. Ghostty stops propagation of modified keys, so the shortcut fails while a terminal has focus. **Fix:** include `new-terminal-tab` in direct dispatch and test both its default and rebound bindings with a focused terminal.

3. **Major — The second terminal binding has no storage or resolution model.** §21.3 promises a separately editable “Close tab, in a terminal” row, while `keymap` and `resolveKeymap` hold one binding per action. It simultaneously says overrides replace only `defaultBinding`, rebinding applies to both contexts, and `terminalBinding` remains unchanged. These rules cannot all hold. **Fix:** define separate binding identifiers and their precedence, persistence, conflict detection, unbinding and reset behavior—or make one override replace both defaults. Test restart and Windows/Linux terminal behavior.

4. **Major — Legacy routine attempt identifiers are unstable and cannot join existing sessions.** [§31.5f](/Users/rajaniraiyn/work/abacusai-bot/docs/rewrite/specs/05-routines-artifacts-library-settings.md:1388) synthesizes `legacy-<at>-<n>` and infers kind from `sessionId`. Existing `CronRun` stores neither kind nor session ID, and `recordRun` prepends entries, changing `n` after every fire. Legacy attempts consequently have unstable keys and null kinds; their actual sessions appear again as unmatched historical rows. **Fix:** persist stable migration IDs, recover valid legacy session references in main, and define an explicit unknown legacy outcome. Test append, truncation, restart and resync without duplicate runs or changing IDs.

5. **Major — Timeout and pause records are incorrectly modeled as additional fires.** §31.5f makes every `recordRun` a distinct attempt, and §7.3 says each displayed attempt represents a fire. However, `reapStuckRoutineRuns` records a timeout for an already-started session; automatic pausing records another administrative entry. A timeout therefore produces two attempts joined to the same session, followed potentially by a sessionless pause rendered as Skipped/Failed. **Fix:** correlate timeout with the original attempt and distinguish administrative history from firing attempts. Define which attempt supplies `RoutineRunRow.result`; test start → timeout → automatic pause.

6. **Major — Routine connector attention links to a report without a connector response card.** [§9.4](/Users/rajaniraiyn/work/abacusai-bot/docs/rewrite/specs/05-routines-artifacts-library-settings.md:664) sends pending connector asks to the run report, citing its `PermissionList`. Connector asks use separate requests and `connectors.respond`; they are not permission descriptors. §7.4 supplies only the report header, whereas 03 r3 explicitly supplies `ConnectorRequestCard`. **Fix:** mount that card for routine reports, including requesting-session MCP refresh before responding, cancellation and decline. Test resolving a real routine connector ask through the attention link.

7. **Major — Auto-reply management loses grants without conversations and removes Revoke for managed grants.** §6.4 sources auto-replies from `bots.senderChats`, which enumerates existing sender sessions rather than grants. Newly approved grants without sessions disappear. §13.3 places Revoke in an approved-people disclosure, but [the snapshot](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/messaging/messaging-gateway-service.ts:2223) deliberately excludes bot-managed grants from `approved`; they live in `autoReplies`, including paused grants. **Fix:** source management from `snapshot.autoReplies`, optionally join conversations, and expose Revoke for approved and paused managed grants. Test grants with no session.

8. **Major — Messaging pairing no longer defines when the connector promise settles.** §12.4 enables the platform and navigates to Messaging, but §13.3’s Done/Cancel actions never resolve the originating `start()` promise. The unchanged request card awaits its `ConnectorOutcome`. The old flow resolves on close only after checking fresh, fully linked gateway state; enabling alone is insufficient. **Fix:** retain the pending request across navigation and settle it exactly once on completed linking or cancellation. Test incomplete WhatsApp linking, shared-platform linking, Escape and successful completion through a chat connector request.

9. **Major — Install failures remain unobservable or hidden.** §31.5h adds `failedPhase` only in the updater’s error-event handler. [Direct install failures](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/main/services/updates/update-service.ts:378) only reset `installing` and return an error; direct check failures also have their own catch path. Moreover, §21.4 hides errors whenever `downloaded` remains true and always retries with `update.check()`, including install failures. **Fix:** populate error and phase in every failure path, prioritize install errors despite downloaded state, retry installation appropriately, and reset immediate-install feedback after rejection. Test thrown `quitAndInstall`, rejected checks and emitted errors.

10. **Major — The critical-update dialog does not stand down after a stalled install.** §21.4 opens the nondismissable dialog whenever `criticalUpdate && downloaded`. The watchdog sets `installStalled` without clearing those flags, so the dialog continues covering the recovery banner. [The old dialog](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer/components/common/critical-update-dialog.tsx:38) explicitly excludes stalled installs. **Fix:** add `!installStalled` and test a critical update transitioning from ready through installing to stalled, with the recovery banner reachable.

11. **Major — Routine OS-notification parity is falsely deferred.** §32.3 says routine OS notifications are “none today.” [The existing root watcher](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer/hooks/use-notifications.ts:20) handles permission requests and completions without excluding routines. In the rewrite, 04’s watcher covers listed sessions, which exclude routines; §9.4 adds attention and a start sound but no routine notification owner. §23.2 also refers to a bot cue watcher calling `system.notify` without defining that producer in 03. **Fix:** assign notification ownership explicitly, consume the shared `ai.runFinished` notice for completion, preserve permission notifications, and apply quiet-hours/per-bot gates. Test actual background notifications, cancellation, deduplication and click routing.

12. **Major — The model-picker amendment drops the requesting thread.** §20.5 requires both local-model entry points to carry `for=<threadId>` so installation adopts the model and returns to the chat. [§31.2](/Users/rajaniraiyn/work/abacusai-bot/docs/rewrite/specs/05-routines-artifacts-library-settings.md:1385) nevertheless directs the model picker to `/settings/models?provider=local`, without `for`; §20.5 explicitly disables Use/adoption in that case. **Fix:** reconcile the amendment and route implementation, including an explicit policy for draft sessions without a persisted ID. Test navigation from the actual picker rather than constructing the Settings query directly.

13. **Major — The credits card discards existing account and expiration safeguards.** §20.4 shows “all your free credits” whenever `creditsExhaustedAt != null`. Existing code distinguishes free/basic/paid/unknown accounts, expires exhaustion marks after 24 hours, and clears stale marks when refreshed counters show headroom. The prescribed card can persist indefinitely and mislabel paid or unread accounts. **Fix:** carry forward tier eligibility, expiration and fresh-counter reconciliation; provide the appropriate paid-account action. Test unknown/paid accounts, expired imported marks and replenished credits.

14. **Minor — The connector wiring calls a React hook from an event callback.** §12.7 prescribes `connect={(id) => useConnectFlow().start(id)}`; §19.3 repeats the pattern. The ported `useConnectFlow` is a hook, so invoking it when the callback runs violates React’s hook rules. **Fix:** call it at component scope and pass `flow.start`, or expose a separately named non-hook command for the module store. Exercise the actual card and referral connect buttons in component tests.

15. **Minor — An empty agent skill list now suppresses the disk baseline.** §15/§31.2 prefers `CUSTOM skills.loaded` once it arrives, including an empty list. [The existing selector](/Users/rajaniraiyn/work/abacusai-bot/apps/desktop/src/renderer/stores/session-skills-store.ts:74) prefers live skills only when nonempty. After an empty agent list arrives, installing a skill and refreshing the baseline can therefore leave the slash menu empty until restart, despite the parity claim. **Fix:** preserve the existing fallback or document and justify the behavior change. Test an empty live list followed by skill installation and baseline invalidation.
