1. **blocker — `apps/desktop/src/main/services/workspace/git-service.ts:1145`** — Discarding a rename overwrites new content at its original path. After `git mv a b`, create a new untracked `a`, then discard `b` with `origPath: "a"`. Only `b` reaches Trash; restoring HEAD destroys the new `a`. Preserve or reject an occupied source before restoring it, and add this collision test.

2. **major — `apps/desktop/src/main/services/workspace/checkout-service.ts:191`** — Backslashes become separators on macOS/Linux, where they are valid filename characters. With both `a\b` and `a/b`, discarding the former restores the latter and destroys unrelated edits. `git-service.ts:1112` repeats the conversion. Preserve literal backslashes on POSIX and test both filenames through checkout operations.

3. **major — `apps/desktop/src/main/rpc/procedures/browser.ts:108`** — `materializeFile` trusts the supplied `hostRoot` without verifying that it belongs to the conversation’s checkout or an allowed artifact folder. A worktree session can supply the primary checkout, or `/`, and expose files and subresources outside its checkout. Derive allowed roots in main and validate the requested root against them.

4. **major — `apps/desktop/src/main/services/workspace/checkout-service.ts:305`** — `git.discard` bypasses migration write blocks. It can trash or restore an unresolved journal destination, undermining recovery and allowing the next rollback to overwrite user changes. Check `isMigrationWriteBlockedTree` for both destination and rename source before any mutation; test explicit destinations and the unknown-destinations block.

5. **major — `apps/desktop/src/main/services/agent-tools/cron-store.ts:104`** — Step 5 makes `cronjobs.json` a journaled migration destination, but its runtime writer ignores migration write blocks. Routine edits and scheduled runs can overwrite it while recovery remains unresolved. Refuse or durably hold those writes, and extend the step-5 harness to exercise runtime writes before recovery succeeds.

6. **major — `apps/desktop/src/main/services/updates/experience/experience-updater.ts:258`** — Renderer-change detection compares against an uncommitted candidate. If renderer B waits for idle, then another release contains B plus a newer agent, the second release takes `commit: true` and persists B without readiness succeeding. Compare against the committed renderer and preserve the pending readiness transaction across releases.

7. **major — `apps/desktop/src/main/services/updates/experience/experience-store.ts:271`** — `commitActivation` captures a candidate, awaits filesystem operations, then unconditionally clears pending activation state. A newer activation during those awaits loses its rollback state, and `active.json` can describe the older candidate while memory describes the newer one. Serialize activation mutations and retain a generation token throughout persistence.

8. **major — `apps/desktop/src/main/renderer-host.ts:234`** — Ordinary swap failures, including rejected loads and load timeouts, only log an error. They neither retry nor report `gave-up`, leaving the failed candidate active and pending indefinitely. Route every unsuccessful swap through bounded retry and abandonment; test rejected loads and timeouts alongside `SwapNotReady`.

9. **major — `apps/desktop/src/main/renderer-host.ts:193`** — Having no renderer host produces `skipped`, which `index.ts:441` commits as successful activation. On macOS, an update received after closing the last window can therefore persist a renderer that never passed readiness. Keep that activation pending until a newly created renderer reports ready; distinguish “already ready” from “no window.”

10. **major — `apps/desktop/src/main/services/session/model-switch.ts:79`** — One model response settles every pending request for the session. 11. **major — `apps/desktop/src/main/services/bots/bot-service.ts:353`** — `pinSession` captures the bot and session models before awaiting the catalog, then applies the stale result.
