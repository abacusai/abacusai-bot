# Shared workspace surfaces

Source: `01-renderer-foundation.md` §5.3/§7, `04-sessions.md` §10, and the artifact's SessionRunning, SessionReview, SessionBrowser, SplitView, FullView and Pickers boards. `styles/tokens.css`, `lib/shell-geometry.ts`, `lib/side-panel/geometry.ts` and `lib/motion.ts` own the values.

- Chrome, rail, primary sidebar, title bar and gutters expose the native window material. Every wrapper behind a Session island stays transparent, including Dockview hosts/groups/sashes. Content islands use `--background` with the shared border; native pane surfaces may use the existing 90% tint. Inactive windows, reduced transparency, translucency off, unsupported material and Linux keep the opaque `--sidebar` fallback.
- Floating sidebars, secondary drawers, promo cards, popovers, menus and overflow lists use the shared solid `--floating-surface-background`, border and shadow. Dock drop targets use its accent tint. Never put a backdrop filter on scrolling content.
- Islands and floating surfaces share `--pane-radius` (12px), `--pane-inset` gutters (8px), and the border token. Title-bar rows are 40px; sidebar rows 32px. Density may change chrome/row heights through the existing preferences.
- Primary sidebar: fixed 280px; Bots strip: fixed 88px; rail: fixed 56px. Docked chat/tool split: both at least 360px; tool default 400px, maximum 960px or 60% of available width while preserving chat's minimum. Widths persist per scope. Expanded dock leaves have native minimums: Chat 360px, tools 280px, height 180px; Dockview owns drag/split/resize and persists per-session layouts.
- Available content width subtracts rail, occupied primary sidebar and outer inset. A pinned primary yields to peek first when an open split cannot fit 728px. The Bots strip stays compact; if the split still cannot fit, Bots use a floating 356px drawer and Sessions show one full-width Chat/tool pane. Narrow expanded Sessions retain their saved dock layout, showing the selected pane until both available dimensions fit Dockview’s actual saved-group minimums (at least 728px wide). These effective modes never overwrite the pin or stored width preferences. Toggles use the same policy; tool-tab navigation preserves an open peek.
- Resizable gutters: transparent 8px hit area, visible 1px divider, 2px accent on hover/drag, resize cursor, focus ring, arrow-key resizing, double-click reset. Splitters stay in gutters. Pointer resizing follows the pointer directly; reset restores the shared default (dock groups split evenly). Fixed rail/primary widths have no handles.
- Use `springs.sidebar` for column/peek movement and `springs.panel` for rail height/active indicators; drawers/promo use the existing cross-fade preset. Reduced motion uses `reducedTransition`; resizing stays direct. Animate opacity/transform for incidental feedback, never `transition: all`.
- One TabsRail occupies the title bar's first row for every dock group, between native caption insets and right controls. No body tab headers duplicate it. Default: exactly one row, compact shrinking tabs, horizontal scroll only on actual overflow, edge fades, active-tab reveal and all-tabs search. Appearance's persisted **Allow two rows of tabs** defaults off and permits a maximum of two rows for 7–12 tabs that fit at ≥480px; never three. Caption controls remain on row one. Add/overflow controls stay reachable.
- Menus render through the UI portal with collision padding, compact icon rows, truncated labels, bounded height and scrolling fades. Full tab titles remain accessible through tooltips; long labels reveal after 400ms of hover or keyboard focus at 32px/s, reversing inside a fixed clip without changing tab width. Reduced motion keeps ellipsis plus the full-title tooltip.
